## 第 1 段 · 思路（权重最高）

> **可直接粘贴：**

**我们要回答的不是「哪里有价差」，而是「这一单该怎么下、以及该不该下」。**

代币化美股（rToken）现货与对应的美股 USDT-M 永续都是 7×24 连续报价，但两条腿在不同时段由不同机制定价：周末与节假日走平台「所内撮合」（`in_house`），工作日走直连美股（`stockroute`）。项目一（同一套技术栈的姊妹项目）已经证明：这条价差**只在所内撮合窗口具有零售可执行性**，而且收益来源是**流动性补偿（做市）**，不是"价差必收敛"。

但能算出"能不能赚"，**算不出"这一单该怎么下"**。执行层有四个真实问题，单靠一个成本公式答不了：

| 执行层的真实问题 | 为什么单靠成本公式答不了 | 我们的做法 |
|---|---|---|
| 这一刻挂单，会不会被逆向选择？ | 需要把"现在有没有信息事件"从**非结构化**新闻与法定申报里读出来 | 事件闸门（SEC EDGAR 一手申报 / 官方 RSS / 财报日历） |
| 两条腿只成交一条怎么办？ | 需要**联合**成交分布，不是两条腿各自的成交率 | 用 30 秒盘口存活区间实测四格分布，**不做独立相乘** |
| 报价在动，但市场还有成交吗？ | 需要把"报价"和"逐笔成交"**两张表联起来**看 | `execution_risk` 分析师提出可证伪假设，进风控后**可真否决** |
| 出了这么多风险信号，谁说了算？ | 需要一个能**一票否决**、且**只收紧不放松**的风控角色 | 风控官：9 条固定规则 + agent 假设驱动的规则 |

**核心假设 H1**：执行决策的输入是**多维、非结构化、相互冲突**的，因此需要多个**独立视角**分别取证，再由一个**强制对抗**的辩论层收敛。

**核心假设 H2（这条更重要）**：**数字不能由 LLM 生成** —— 否则报告里的每个数字都无法复跑。所以系统被切成两半：

| 谁 | 做什么 | 为什么 |
|---|---|---|
| **Agent（5 路事前独立分析 + 多空辩论 + 风险假设 + 第 6 路执行进度官）** | **发现与论证** | 需要把跨表事实联系起来（例：现货报价在刷新、但已数小时无成交），规则写不全 |
| **LLM（运行期只有一处）** | 从新闻/申报里判断"是不是信息事件" | 输入是非结构化的，这是规则写不全的部分 |
| **确定性代码** | 成本数字 / 最优执行方式 / 一票否决 / 最终规模 | 门槛与规模**必须可复跑**（同输入 → 同一 `decision_hash`） |

**决策逻辑（每一步都能单独复跑）**：

```
5 路事前独立分析（互不读对方结论）+ 第 6 路**执行进度官**（执行中，需在途订单）
  ├─ 📊 基差成本（实测：摩擦预算、资金费）
  ├─ 😱 情绪拥挤度（资金费结构）
  ├─ 📰 事件/新闻（LLM 唯一的活）
  ├─ 📈 盘口与成交（5 档盘口 + 逐笔成交，我方独有）
  └─ 🛡️ 执行风险（把"这一单可能怎么死"写成可证伪假设）
        ↓ 只保留有实测量的结论（无证据 → 作废）
   🐂 多头立论  ⇄  🐻 空头立论（每条论点必须给证伪条件；同一证伪条件只算一条）
        ↓ 交叉质证（必须指名对方最强一条并复述其证伪条件）
   裁决（确定性）：得分差 ≥ 0.25 才有倾向，否则"僵持 = caution"
        ↓
   事件闸门（LLM）：severity=block → **挂单类方案直接作废**（硬规则）
        ↓
   交易员：规模/价位/方式/拆几笔（不新造阈值、不做价格预测）
        ↓
   风控官：9 条固定规则 + agent 假设驱动的规则 → 一票否决 / 缩规模 / 强制吃单
        ↓
   最终决策 + 可复跑日志（参数、全部阈值、输入 SHA256、四层留痕、decision_hash）
```

**风控设计（本项目的核心差异点）——两条线同时管，缺一条都不成立**：

1. **硬规则（代码）**：事件窗口内禁挂单；成本越线**且**毛边际不足则否决；逆向选择过深则否决；**数据缺失按最保守处理**（缺数据 ≠ 没有风险）。
2. **Agent 提出的风险假设**：每条必须四要素齐全 —— **假设 + 实测量 + 验证阈值 + 证伪条件**，缺一即丢弃并留痕；经映射变成可执行的风控动作，日志里以 `agent:` 前缀标识。

🔴 **单调性硬约束**：`最终立场 ≤ 辩论立场`，`最终规模 ≤ 交易员规模 ≤ 风控规模上限`。
自检里用 **3 立场 × 3 闸门状态穷举**验证它 —— **任何一环只能收紧，不能放松**。这一条是"一票否决"能不能算数的分界线。

**Alpha 来源说明（手册要求的必填项）**：我们实测发现 **taker 路线被点差吃穿** —— 两腿全吃单的往返手续费是 22.00 bp，挂单类最低可到 14.00 bp，而现货腿点差中位只有约 7–10 bp 量级（出处：`data/derived/friction_budget.csv` 的 `fee_perp_taker_bp=22.0` / `fee_all_maker_bp=14.0`）。**据此把策略从"吃单套利"正名为"做市型价差捕获"**，并把成本门槛作为唯一的日内开关。这不是叙事选择，是被实测数字逼出来的路线修正。

## 第 6 段 · 对 AI Trading 的看法（选填）

> **可直接粘贴。**

**第一点：AI 在交易里的价值，取决于它能不能被证伪。**
我们在开发期让大模型做了大量工作，但它最有价值的产出不是"算出了什么"，而是**推翻我们自己的结论** —— 包括一条已经写进文档、并被当成风险项的数字（"rToken 跟踪偏离 −33~+85 bp"），被实测否掉后**整段撤回**（`docs/14` §4.2）。**一个不会推翻自己的 AI 交易系统，只是在给已有的偏见加速。**

**第二点：AI 在运行期最合适的位置是"判断"，不是"下单"。**
在本项目里我们把这条边界写进了代码结构，而不是写在 PPT 里：

- 数值计算（成本 / 成交概率 / 门槛 / 最终规模）**全部由确定性代码给出**，同输入必然同输出、同一个 `decision_hash`；
- 大模型在运行期**只有一个职责**：判断"现在是不是信息事件窗口"（输入非结构化，规则写不全）；
- **没有可回溯来源时置信度封顶 0.40**，且**无 key / 调用失败时按保守原则暂停挂单**，并在输出里**如实标注"本次未使用 LLM"**；
- Agent 可以提出风险假设，但**只能收紧、不能放松**（单调性由 3×3 穷举自检保证）。

**第三点：多 Agent 最容易变成表演，所以我们给它上了三道锁。**
没有引用已实测量的结论一律作废；给不出证伪条件的论点一律作废；**同一证伪条件只算一条**（防止"一个判断换三个说法"显得很严谨）。证据还按强度加权（实测 1.00 / 外部可回溯 0.85 / 再计算 0.60 / 机制推断 0.30）—— 因为**不可证伪的东西不该和逐笔实测同权**。

**第四点（给工具方的一点建议）**：`bitget-signal` 免 Key 的定位对我们是**最理想**的感知层，但我们实测其 `news_feed` 对全部 44 个源返回空 items，所以这条能力目前**用不上**。如果官方能提供稳定的新闻聚合与官方公告流，AI Trading Desk 那类"事件感知"功能才能真正落地 —— 我们现在的替代方案是自己抓 SEC EDGAR 一手申报与官方 RSS。
