### 1.1 为什么推荐"赛道三为第二次提交"

1. **评分机制不相关 = 风险不相关。** 项目一投赛道一开放主题/具名子主题，吃的是**纯量化评分**；项目二投赛道三，吃的是**纯评委主观评分**。两个池子不会因为同一个原因同时失分。
2. **项目二的强项恰好是赛道三点名的三件事。** `docs/40` §8 甲套已逐项对应："大单拆分"（拆单笔数 = 规模 ÷ 单笔粒度）、"盘口深度分析"（自采 5 档盘口，首档深度直接做规模上界）、"滑点模式调整"（三种执行方式并排取最优，`severity=block` 时挂单类被硬作废）。这不是包装，是代码里就有的东西（`project2/agent_team.py` 的 `trader()`、`project2/execution_cost.py`）。
3. **赛道一的量化硬材料项目二给不出来。** 赛道一评审重点写的是 Sharpe / Sortino / 最大回撤 / 换手率 / 样本外衰减（项目一仓库 `docs/00` §2.3），而项目二**不下单**，没有持有期损益，也就**没有事后标签**（`docs/36` §2.1 就是这么写的）。硬凑会把"没有绩效数据"暴露成主要印象。
4. **名额结构上具名题的对标成本更低。** 具名题和开放题都是"每题 1 名"，但具名题**评委已经明确"这题该做什么"**（项目一仓库 `docs/00` §2.1 的第 2 条），跑偏风险更小 —— 对"执行辅助"这种定位清晰的题目尤其有利。
5. **手册允许两投，不用白不用。** 手册原文："一支队伍最多向 **2 个不同主题**提交，**每个主题须是独立项目，分两次填表**"（项目一仓库 `docs/31` §0）。

### 1.2 什么情况下改用乙套（赛道一开放主题）

- 若**只能投一次**，且项目一的量化材料已经吃满赛道一 —— 那项目二就**不投**，把执行层写进项目一的"核心竞争力"（项目一仓库 `docs/23` 修正 2 的 ⚠️ 建议）。
- 若**赛道三 Demo 最终无法做到公网可访问**，而项目一可以代为承载 —— 赛道三"重视可访问"（`TASKS-P2.md` T1），此时乙套更稳。
- 两套措辞都在 `docs/40` §8，**切换成本只是换一段文字**，其余 6 段、独立字段、局限清单**完全通用**。

## 3. 本仓库为什么是一个**独立项目**

> 手册硬要求：两投"**每个主题须是独立项目**"（项目一仓库 `docs/31` §0）。
> 下面是**可核验的证据**，不是声明。

### 3.1 证据 1：自检可以独立跑通，不碰项目一

```powershell
python run_p2.py --selftest          # 全部 [OK] / 0 失败，退出码 0，不需要网络、不需要 LLM key（本次实跑 185–186 项）
python project2\agent_team.py --selfcheck   # 单独跑 agent 层：82 项 [OK] / 0 失败
python run_p2.py --demo NVDA         # 命令行跑完整决策链
```

自检命令串起来的三个模块是 `project2/execution_cost.py`（12 项）、`project2/agent_team.py`（82 项）、`project2/event_gate.py`（38 项）（见 `run_p2.py` 的 `--selftest` 分支），**全部在本仓库内**，三个模块单跑各自均为 0 失败。

### 3.2 证据 2：独立数据快照，可逐文件核验

```powershell
python tools\snapshot_manifest.py --verify   # 核验 19 项 / 39.9 MB（冻结快照 16 项），逐字节核验，退出码 0
```

边界与逐文件说明（复制 / 截断 / 尾行截断、字节、行数、SHA256 前 16 位、用途）写在 `data/SNAPSHOT.md`。
关键边界：盘口按轮次截断（保留前 120 轮）、`trades-2026-09-14` 与 `trades-2026-09-19` 尾行截断（各保留最后 80,000 行）。
⚠️ **这是我们如实标注的截断，不是"数据不全"的借口** —— 交易所不提供历史 bid/ask，盘口是时点快照，**停止采样即永久丢失**。

### 3.3 证据 3：零第三方依赖

- 代码只用 **Python 标准库**（`argparse` / `csv` / `json` / `hashlib` / `http.server` / `urllib` / `zoneinfo` / `statistics` / `datetime` …）。
- 仓库内**没有** `requirements.txt` / `pyproject.toml` / `setup.py` / `Pipfile`（可自行 `Get-ChildItem -Recurse -Include requirements*.txt,pyproject.toml` 验证，结果为空）。
- 实测环境 Python **3.14.5rc1**。
- 因此评审方 `git clone` 后**不需要 `pip install` 任何东西**，直接 `python run_p2.py --selftest` 即可验证。

### 3.4 证据 4：不依赖项目一的运行

| 项 | 事实 |
|---|---|
| 启动 | `python run_p2.py`（默认 `http://127.0.0.1:8788`），**不读项目一的任何路径** |
| 无 key | 事件判断退化为确定性日历，并在输出里**如实标注"本次未使用 LLM"**，同时因保守优先**暂停挂单**（`project2/event_gate.py` 的 `FAIL_CLOSED_ON_LLM_ERROR = True`） |
| 无网络 | 自检与演示**全部离线可跑**（`python run_p2.py --selftest` 不需要网络） |
| 数据 | 只读 `data/` 下的 19 项快照 |
| 接口 | 与项目一的关系是**单向只读**：项目二读快照，项目一**不读**项目二；反向依赖为零 |

### 3.5 证据 5：与项目一的**实质差异**（不是同题拆两半）

| 问题 | 谁回答 | 交付物 |
|---|---|---|
| **哪里有价差？哪个时段才可执行？** | 项目一 | 策略代码 + 回测记录 + 越线率（项目一仓库 `docs/31` §3.1） |
| **这一单怎么下、能不能下？** | 项目二（本仓库） | 执行成本模型 + Agent 团队四层 + 事件闸门 + 可复跑日志（`docs/40` 第 1 段） |

一句话：**项目一回答"哪里有价差"，项目二回答"这一单怎么下"。** 两者共用同一套自采数据与同一份口径文档，但**产出物、评分机制、赛道定位完全不同**。
