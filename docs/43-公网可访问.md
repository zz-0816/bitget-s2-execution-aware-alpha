## 0. 先分清三件事

| | 本机 | 公网 | 说明 |
|---|---|---|---|
| 默认启动 | ✅ `http://127.0.0.1:8788` | ❌ | `python run_p2.py`。**只有本机能开** |
| 对外监听 | ✅ | ✅（需放行端口） | `python run_p2.py --host 0.0.0.0` |
| 临时公网链接 | ✅ | ✅ | `python run_p2.py --tunnel`（cloudflared，免账号） |
| 长期公网 | ✅ | ✅ | Render / Fly / 自备服务器，见 §3 |

⚠️ **一个必须知道的边界**：本仓库的页面是**只读**的 —— 所有 `/api/*` 都是 GET，
没有任何写入、下单、改数据的端点。所以把它挂到公网的安全面**只有"别人能看到你的
分析结果"**，不涉及资金与账户。但仍然不建议在存有 API key 的机器上长期开着隧道
（那是机器层面的问题，不是本项目的问题）。

## 1. 路线 A：临时公网链接（推荐用于**提交当天的验收与截图**）

### 1.1 装 cloudflared（单文件，免账号）

| 系统 | 做法 |
|---|---|
| Windows | 下载 `cloudflared-windows-amd64.exe`，放到 `%TEMP%` 或 `tools\bin\`（本程序会自动找到） |
| macOS | `brew install cloudflared` |
| Linux | 下载对应架构的单文件二进制，`chmod +x` 后放进 PATH |

> 用 Python 下载（PowerShell 的 `Invoke-WebRequest` 在某些机器上会因 TLS 报
> "基础连接已经关闭"，用 Python 反而稳）：
> ```powershell
> python -c "import urllib.request,os;u='https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe';o=os.path.join(os.environ['TEMP'],'cloudflared.exe');urllib.request.urlretrieve(u,o);print(o)"
> ```

### 1.2 一条命令起服务 + 隧道

```powershell
python -u run_p2.py --tunnel --port 8788
```

（Windows 也可以直接双击 `一键开公网Demo.cmd`；Linux/macOS 用 `./start_demo.sh`。）

### 1.3 实测记录（2026-09-19，本机 Windows）

```
  ✅ 公网地址：https://gratuit-discounts-dan-domains.trycloudflare.com
```

然后**从公网侧**回打一遍，确认不是"只有我自己能开"：

```
OK   /api/health 200 720 bytes 3.6 s
     bases: 10 | snapshot: 2026-09-18 19:19 UTC | llm: False
OK   /          200 5501 bytes 2.4 s
     title: 执行决策台 · Execution-aware Alpha（项目二）
```

### 1.4 这条路的**代价**（必须写清，不然就是误导）

1. **临时**：进程一停链接就失效 —— 评委晚一天点就是 404。
2. **域名随机**：每次启动都不一样，所以**必须在提交前重新生成并把截图/录屏存档**。
3. **不适合长期挂**：它的定位是"提交那几天的可访问性证明"，不是部署方案。

## 3. 路线 C：一键部署（半永久地址）

### 3.1 Render（最省事，免费层）

1. 把本仓库推到 **公开** GitHub 仓库；
2. Render 控制台 → **New +** → **Blueprint** → 选中本仓库；
3. 它会读到 `render.yaml`，直接创建服务；
4. 部署完成后 `https://<服务名>.onrender.com` 就是你的提交链接。

已在本仓库里配好的东西：

| 文件 | 作用 |
|---|---|
| `render.yaml` | 服务定义 + 健康检查 `/api/health` |
| `requirements.txt` | **空依赖**（纯标准库），构建几秒完成 |
| `run_p2.py` | 认 `$PORT` 环境变量，并在设了 `$PORT` 时**自动对外监听** |

⚠️ 免费层的代价：**会休眠**，冷启动约 30 秒。评委点开可能要等一会儿 ——
这正是为什么 §2 的截图/录屏不能省。

### 3.2 Fly.io

```bash
fly launch --no-deploy --copy-config
fly deploy
fly open
```

配置在 `fly.toml`（已设 `internal_port = 8788`、健康检查、自动停机）。

### 3.3 任意 Docker 环境

```bash
docker build -t execution-aware-alpha .
docker run --rm -p 8788:8788 execution-aware-alpha
# 验证镜像完整性（含全量自检）：
docker run --rm -it execution-aware-alpha python run_p2.py --selftest
```

- `Dockerfile` 用 `python:3.12-slim`，**并装了 `tzdata`** ——
  因为 `common/market_calendar.py` 用 zoneinfo 读 `America/New_York` 判美股时段，
  而 Debian slim 镜像默认没有 tz 数据库（**在 Windows 上不会暴露这个问题**）。
- `HEALTHCHECK` 直接打本仓库自己的 `/api/health`，不引入额外工具。

### 3.4 自备服务器（有自己的机器/域名时）

```bash
# ① 起服务（对外监听，但建议只让反代能访问）
python -u run_p2.py --host 127.0.0.1 --port 8788

# ② nginx 反代（示例）
#   location / { proxy_pass http://127.0.0.1:8788; proxy_set_header Host $host; }
```

⚠️ 不要把 `--host 0.0.0.0` 直接暴露在公网而不加反代/防火墙 ——
本项目没有鉴权，也没有必要加（它不写任何东西），但"裸奔一个 HTTP 服务"
本身不是好习惯。

## 4. 常见故障（都实际踩过或差点踩到）

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器里起来了，外面 404/超时 | 只听 `127.0.0.1` | 用 `--host 0.0.0.0`，或设 `PORT` 环境变量（此时会自动对外监听） |
| `--tunnel` 没打印公网地址 | cloudflared 没装 / 不在 PATH | 放进 `%TEMP%`、`tools\bin\`，或用 `--cloudflared <路径>` 指定 |
| 公网地址打在日志里但看不到 | 输出被重定向，缓冲区没刷新 | 用 `python -u`；程序内部对公网地址这一行已强制 flush |
| 页面打开是空的 | **历史故障**：端点对不上 | 现在 `python run_p2.py --selftest` 会真去打每个端点，并额外用 Node 渲染一遍页面 |
| Linux 容器里报 `ZoneInfoNotFoundError` | slim 镜像没 tzdata | 见 §3.3，Dockerfile 已处理 |
| `python` 版本过低报 `AttributeError: UTC` | 用了 `datetime.UTC`，需 3.11+ | 升到 3.11+（README 已写明） |
