## 0. 为什么需要一个保活进程

`python run_p2.py --tunnel` 有个致命的使用问题：**进程一掉，公网链接就死了**，
而临时隧道的域名**每次重启都会变**。评委可能在任何时间点开你的链接，
所以我们需要三件事：

| 需求 | 做法 |
|---|---|
| **自愈** | 子进程崩溃/断网/被误关 → 自动重启（指数退避，不会疯狂刷日志） |
| **可查** | 不管重启多少次，**当前**公网地址固定写在 `data/run/public_url.txt` |
| **可控** | 单实例（不会起两份抢端口）、能干净停（**连子进程树一起收**） |

任意平台（Linux/macOS）等价命令：

```bash

python tools/keep_alive.py --stop     # 停止

```

## 2. 它到底做了什么

```
keep_alive.py（守护）
  ├─ 单实例检查（PID 文件 + 端口占用）
  ├─ 清掉上一轮可能残留的**孤儿隧道**（父进程已死、连的是本端口）
  ├─ 起子进程：python run_p2.py --port 8788 --tunnel
  │     └─ run_p2.py 再拉起 cloudflared（临时隧道）
  ├─ 实时读子进程输出 → 写日志 + 打印 + **正则抓公网地址**
  │     └─ 抓到就写 data/run/public_url.txt 与 status.json
  └─ 子进程退出 → 记录退出码 → **退避后重启** → 循环
```

| 机制 | 参数 | 说明 |
|---|---|---|
| 退避 | `--backoff-min 5` → `--backoff-max 60` | 5→10→20→40→60（封顶）；活过 `--stable-seconds 120` 就重置 |
| 崩溃循环告警 | `--crash-max 5` / `--crash-window 300` | 窗口内退出太多次就**明确报警**（仍然继续重启，不会放弃） |
| 状态落盘 | `data/run/status.json` | 机器可读：state / pid / port / url / restarts / 上次退出码 |
| 地址落盘 | `data/run/public_url.txt` | 一行纯文本，方便脚本和"手滑忘了地址"时读 |
| 日志轮转 | `data/run/logs/demo-*.log` | 只保留最近 10 份 |

### 2.1 ⚠️ 为什么必须"连子进程树一起杀"

`run_p2.py` 会再拉起 `cloudflared`。**只 kill 父进程不会带走孙进程** ——
cloudflared 会变成孤儿一直挂着，而守护每重启一次就多挂一条隧道。
所以停止时用 `taskkill /F /T`，重启前还有一道 `kill_orphan_cloudflared()`
专门清理"父进程已死 + 命令行里含本端口"的残留（**只碰自己那一类**，
不动本机上其它项目的进程）。

### 2.2 一个真实踩坑：`.bat` 里不能有中文

最初启动逻辑直接写在 `.bat` 里（含中文注释与 `echo`），在中文 Windows 上直接崩：

```
'xit' is not recognized as an internal or external command
'长期运行与保活.md。' is not recognized ...（这行本来是 REM 注释）
```

原因是 **cmd.exe 按当前代码页逐字节解析批处理文件**，而文件是 UTF-8：
多字节汉字会把紧跟其后的换行/首字符一起吃掉，于是 `exit /b 0` 变成 `xit`。
**这类故障只在中文内容/中文路径下出现，英文环境测不出来。**

现在的分工是：

| 层 | 语言 | 职责 |
|---|---|---|
| `.bat` | **纯 ASCII** | 找 Python、转交参数、`pause` |
| `tools/demo_launcher.py` | Python | 环境预检、前后台启动、状态展示（**所有中文提示**） |
| `tools/keep_alive.py` | Python | 守护循环、地址抓取、清理 |

> 📌 `.bat` 还必须用 **CRLF** 换行：纯 LF 的批处理在被 cmd 解析时同样会串行。
> `.gitattributes` 里已经把 `*.bat` 标成 `eol=crlf`。

## 3. 诚实边界：它**能**扛什么、**扛不住**什么

| 情况 | 扛得住吗 | 说明 |
|---|---|---|
| 子进程崩溃 / 端口被占后释放 / 代码抛异常 | ✅ | 退避后自动重启 |
| 临时隧道掉线（cloudflared 自己退出） | ✅ | 子进程退出 → 重启 → 换一条新隧道 |
| 启动窗口被关（用 `后台运行Demo.bat`） | ✅ | 进程已脱离该窗口 |
| **注销登录 / 关机 / 休眠** | ❌ | 进程随会话结束。见 §4 |
| **公网域名保持不变** | ❌ | quick tunnel 每次重启**换域名** —— 地址文件会更新，但**旧截图里的链接会失效** |
| 隧道被墙 / 网络整体中断 | ⚠️ | 会不断重试；网络恢复后自动可用 |

> 🔴 **提交材料里必须写清**：这是**临时**链接，失效后按 `docs/43` 一条命令重开。
> 把临时链接写成"永久服务"是**不实陈述**，比链接失效更糟。

## 4. 想真的"开机就活着"：任务计划程序

`后台运行Demo.bat` 只解决"窗口被关"，不解决"关机/注销"。要跨重启存活，
用 Windows 任务计划程序（**不需要管理员**，当前用户即可）：

```powershell
# 登录时自动启动（最小化窗口），示例路径按你的实际目录改
schtasks /create /tn "P2-Demo-KeepAlive" /sc onlogon /rl limited ^
  /tr "cmd /c cd /d D:\bitgetS2_trading_agent && py -3 -u tools\keep_alive.py --port 8788"

# 立即跑一次（不用等下次登录）
schtasks /run /tn "P2-Demo-KeepAlive"

# 不想要了就删掉
schtasks /delete /tn "P2-Demo-KeepAlive" /f
```

另外把电源计划设成**不睡眠**（否则机器睡了，服务就断了）：

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
```

> 更稳的做法其实是 `docs/43` §3 的 Render/Fly：那才是"关机也在线"，
> 代价是免费层会休眠（冷启动约 30 秒）。**两条腿都留着**最稳。
