```
【第一段 · 思路】

我们要回答的不是「哪里有价差」，而是「这一单该怎么下」。代币化美股（rToken）现货与对应的美股 USDT-M 永续都是 7×24 连续报价，但在不同时段由不同机制定价：周末与节假日走平台「所内撮合」（区分 maker/taker），工作日走直连美股（全部按 taker 计费）。姊妹项目已证明这条价差只在「所内撮合」窗口具有零售可执行性，且收益来源是流动性补偿（做市），不是"价差必收敛"。但能算出"能不能赚"，算不出"这一单该怎么下"。

执行层有四个真实问题，单靠一个成本公式答不了：
1) 这一刻挂单会不会被逆向选择？—— 要把"现在有没有信息事件"从非结构化的新闻与法定申报里读出来；
2) 两条腿只成交一条怎么办？—— 需要"联合"成交分布，不是两条腿各自的成交率相乘；
3) 报价在动，但市场还有成交吗？—— 要把"报价"和"逐笔成交"两张表联起来看；
4) 出了这么多风险信号，谁说了算？—— 需要一个能一票否决、且只收紧不放松的风控角色。

核心假设 H1：执行决策的输入是多维、非结构化、相互冲突的，因此需要多个独立视角分别取证，再由一个强制对抗的辩论层收敛。
核心假设 H2（更重要）：数字不能由 LLM 生成，否则报告里每个数字都无法复跑。所以系统被切成两半——Agent（5 路事前独立分析 + 多空辩论 + 风险假设 + 第 6 路执行进度官）负责"发现与论证"；确定性代码负责"成本数字 / 最优执行方式 / 一票否决 / 最终规模"；LLM 在运行期只有一个职责：判断"现在是不是信息事件窗口"。

决策逻辑（每一步都能单独复跑）：5 路事前独立分析（互不读对方结论：基差成本 / 情绪拥挤度 / 事件新闻 / 盘口与成交 / 执行风险）→ 只保留有实测量的结论（无证据即作废）→ 多头立论 ⇄ 空头立论（每条论点必须给证伪条件，同一证伪条件只算一条）→ 交叉质证（必须指名对方最强一条并复述其证伪条件）→ 确定性裁决（得分差 ≥0.25 才有倾向，否则"僵持 = 谨慎"）→ 事件闸门（severity=block 时挂单类方案直接作废，硬规则）→ 交易员出方案（规模/价位/方式/拆几笔，不新造阈值、不做价格预测）→ 风控官（9 条固定规则 + agent 假设驱动的规则，一票否决 / 缩规模 / 强制吃单）→ 最终决策 + 可复跑日志（参数、全部阈值、输入 SHA256、四层留痕、decision_hash）。

风控设计（本项目的核心差异点）——两条线同时管，缺一条都不成立：
1) 硬规则（代码）：事件窗口内禁挂单；成本越线且毛边际不足则否决；逆向选择过深则否决；数据缺失按最保守处理（缺数据 ≠ 没有风险）。
2) Agent 提出的风险假设：每条必须四要素齐全——假设 + 实测量 + 验证阈值 + 证伪条件，缺一即丢弃并留痕；经映射变成可执行的风控动作，日志里以 agent: 前缀标识。
硬约束：最终立场 ≤ 辩论立场，最终规模 ≤ 交易员规模 ≤ 风控规模上限。自检用 3 立场 × 3 闸门状态穷举验证——任何一环只能收紧，不能放松。这一条是"一票否决"能不能算数的分界线。

Alpha 来源说明（手册必填项）：我们实测发现 taker 路线被点差吃穿——两腿全吃单的往返手续费是 22.00 bp，挂单类最低可到 14.00 bp，而现货腿点差中位只有约 7–10 bp 量级。据此把策略从"吃单套利"正名为"做市型价差捕获"：收益来自流动性补偿，而不是"价差必收敛"；并把成本门槛作为唯一的日内开关。这不是叙事选择，是被实测数字逼出来的路线修正。

第一，AI 在交易里的价值，取决于它能不能被证伪。开发期大模型最有价值的产出不是"算出了什么"，而是推翻我们自己的结论——包括一条已经写进文档、并被当成风险项的数字，被实测否掉后整段撤回。一个不会推翻自己的 AI 交易系统，只是在给已有的偏见加速。

第二，AI 在运行期最合适的位置是"判断"，不是"下单"。我们把这条边界写进了代码结构而不是 PPT：数值计算（成本/成交概率/门槛/最终规模）全部由确定性代码给出，同输入必然同输出、同一个 decision_hash；大模型在运行期只有一个职责——判断"现在是不是信息事件窗口"；没有可回溯来源时置信度封顶 0.40；无 key 或调用失败时按保守原则暂停挂单，并在输出里如实标注"本次未使用 LLM"；Agent 可以提风险假设，但只能收紧、不能放松（由 3×3 穷举自检保证）。
```
