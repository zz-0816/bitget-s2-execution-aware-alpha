## 1. 缺陷：`severity=block → 挂单作废` 这条硬规则，**对 LLM 的判断不成立**

文档（`docs/33` §0 ③、`docs/34` §1.2）写的是：

> 🔴 `severity=block` → **挂单类方案直接作废**（硬规则，agent 不能推翻）

而**实现**里，硬闸门走的是：

```
run_decision → execution_cost.consult_gate() → event_gate.static_gate()
```

也就是**只读确定性日历、从不问 LLM**。LLM 的判定只到了辩论层（变成 `analyst_news` 的一条证据）。
后果两条：

| # | 后果 | 说明 |
|---|---|---|
| ① | **安全上** | LLM 判出 block（例如刚披露的 8-K）时，**挂单类方案照样生成** —— 而"挡不住突发新闻与财报"恰恰是我们自己写在局限里的最大缺口 |
| ② | **观感上** | 配上 key 之后页面自相矛盾：闸门区块写"本次未使用 LLM"，而它上面的新闻分析师写"✅ 本次由 LLM 判事件" |

### 1.1 确定性证据（不含任何 API 调用）

把 `event_gate.assess`（`analyst_news` 用的那条 LLM 路径）**打桩成必定返回 `block`**，
跑全部 10 个标的：

```
news 分析师收到 block ：True
硬闸门收到 block     ：False      cost['gate_severity']='none'、maker_allowed=True
挂单被硬规则禁止     ：False
```

### 1.2 ⚠️ 但要公平地说：它当时**没有改变任何结论**

那 10 个标的**全都因为别的原因**（现货腿长时间无成交 → `agent:stale_quotes`、
辩论 stand_down 等）已经 `stand_down` 了，所以这个缺陷当时**不产生任何错误决策**。

**它是潜伏的**：等现货腿恢复成交、策略真正变得可执行时才会咬人 ——
而那正是最需要事件闸门的时候。所以不能因为"现在没事"就不修。

## 2. 修法：合并成一个硬闸门，且**只取更保守的一侧**

```python
# project2/agent_team.py
g = merge_gate(static_gate, news_ev)   # 日历 vs LLM，取更严的
apply_gate_to_cost(cost, g)            # 写回 cost：trader / 风控官读的是它
```

三条设计约束：

1. **只收紧不放松**：两侧取严重度更高的那个（`none < caution < block`）；
   谁更严就让谁当 `source`，并在 `reason` 里写明另一侧说了什么 —— 不藏。
2. **不额外调 LLM**：复用 `analyst_news` **已经算出来的那次判定**
   （这也是不能直接在 `consult_gate()` 里调 LLM 的原因：`--all` 跑 10 个标的
   会变成 10 次额外 API 调用）。
3. **必须同时写回 `cost`**：否则会出现"闸门字段说 block，而 `best_mode`
   还是『双腿全挂单』、`maker_allowed` 还是 True"的自相矛盾。
   `apply_gate_to_cost()` 复刻 `analyse_two_leg()` 里同一套处理（挂单类进 `invalidated`）。

## 3. 🔴 连带修好的两处**复跑契约**问题（这才是真正的坑）

硬闸门一旦依赖 LLM，`--replay` 就不再确定（LLM 是活输入）。把"LLM 判定"当成
**可冻结的输入**记进日志之后，暴露出两个**先前就存在**的问题：

### 3.1 `parameters.now_ms` 记的是**墙钟**，而决策用的是**基准时刻**

`run_decision` 用 `time_basis()` 定"现在几点"（读冻结快照时 = **数据自带时刻**），
但 `build_log` 往 `parameters.now_ms` 里写的是**墙钟**。两者能差好几小时，于是
`--replay` 拿着墙钟重算 —— 而"行情停滞/停牌"是**按龄判据**：

| | now_ms | 现货腿停滞 | 结果 |
|---|---|---|---|
| 原 run（`basis=asof`） | 数据时刻 07:27 | **13.6 分钟** | 未过 30 分钟阈值 → 无假设 |
| 复跑（`basis=explicit`） | 墙钟 23:26 | **572.1 分钟** | 过阈值 → `agent:stale_quotes` **veto** |

→ 契约字段 `rules_skeleton` / `degrade` 直接不一致，真实 CLI
`--log` → `--replay` **报失败**。（这是 `time_basis` 那笔改动带进来的回归，
只是被这次的改动顺手照出来了。）

**修法**：`parameters.now_ms` 记**决策实际使用的时刻**（`decision.time_basis.now_ms`），
传入值只作兜底。

### 3.2 `llm_event.frozen` 不该进契约

`frozen` 说的是"这份判定是**实时**拿到的还是复跑时**冻结**输入的" ——
两次运行必然一个 `false` 一个 `true`。它是**过程信息**，留在契约里会让复跑必然不一致。
**修法**：写进日志时剔除 `frozen`（展示层照旧保留，页面仍能看出是复用的判定）。

## 4. 现在「LLM 判 block」的完整闭环（自检里钉住了）

```
LLM/冻结判定 severity=block
  → merge_gate 取更严的一侧           → effective=block
  → apply_gate_to_cost                → maker_allowed=False、挂单类进 invalidated
  → decide(): 硬闸门优先于辩论        → st_gate=stand_down
  → trader(): allowed=False           → 只剩「双腿全吃单」，无挂单方案
  → 最终 stand_down，规模 0，无订单
```

自检新增 8 条断言（`agent_team.py --decision-selftest` 的 ⑫ 段），其中关键三条：

| 断言 | 防的是什么 |
|---|---|
| LLM 冻结判 block → 硬闸门 effective=block、`maker_allowed=False`、挂单类进 `invalidated` | 本次修的那个缺陷复发 |
| LLM 判 none → **不产生虚假 block** | 修过头变成"总是停手" |
| 用日志参数 + 冻结判定复跑 → `replay_check` 通过；把判定由 block 改成 none → **必须报不一致** | 契约被悄悄绕过／`llm_event` 变成装饰字段 |

## 5. 诚实边界

1. **旧日志没有 `llm_event` 字段**：用它们复跑会**真的再调一次 LLM**，
   结果不一致属于**如实暴露**，不是复跑机制坏了。`--replay` 会打印一条明确提示。
   （仓库里 7 份历史日志属于这一类。）
2. **合并只做严重度**：LLM 的 `reason` / `confidence` 不参与合并计算，
   只进 `reason` 文本与留痕。**数字仍然全部来自确定性代码**（红线未破）。
3. **前端布局验收在本机是跳过的**：那一步要真启动浏览器，本开发沙箱里 Chrome
   启动即退出。已把它归类为"环境问题 → 跳过（退出码 3）"，
   与"页面真的检查不过（退出码 1）"区分开 —— 见 §6。

## 6. 顺手修掉的第三处：前端验收的优雅降级

`tools/ui_check.py` 的注释写着"没有 Chrome/Edge 时**优雅跳过**，
不能因为缺浏览器就让整套自检变红"，但**"装了浏览器却起不来"**这条路径没有降级，
会把整套自检染红。现在：

| 情形 | 退出码 | 处理 |
|---|---|---|
| 没装 Node / 没装浏览器 | 0 | `[skip]` |
| **装了但起不来**（受限策略、无桌面会话、profile 被锁） | **3** | `[skip]` —— 与环境同等对待 |
| 页面真的检查不过（溢出/字面 `**`/截断） | 1 | **`[FAIL]`** |

判定**不靠匹配中文报错文本**：`ui_shot.js` 在"调试端口连不上"时给 error 打
`envFailure` 标记并 `process.exit(3)`，`ui_check.py` 按退出码分流。
