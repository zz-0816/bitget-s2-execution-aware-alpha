## 0. 一句话说清 v1 → v2 改了什么

**v1 是「开仓前的一次性决策」；v2 把它补成「执行中的闭环」。**

赛道三「执行辅助」手册原文要的是：**trader 决策后**，AI 如何负责**拆单与滑点管理**——
大单拆分、盘口深度分析、滑点模式调整。

对照下来 v1 有三个**结构性**缺口（不是调参能解决的），另有两处该补的约束：

| # | 缺口 | 现在什么状态 | v2 补法 |
|---|---|---|---|
| 1 | **没有挂单队列位置模型** | 成交概率用历史实测率近似，**不含排队** | 新增 🔬 微观结构分析师 |
| 2 | **只有开仓前一次决策** | 挂单没成交 / 部分成交时，链路里**没有人负责** | 新增 ⏱️ 执行进度官 |
| 3 | **拆单粒度是常量** | `SLICE_USD=2000`、`DEPTH_TAKE_RATIO=0.25` 写死，对流动性不敏感 | 新增 ✂️ 拆单规划器（**确定性代码，不是 agent**） |
| 4 | **无账户级约束** | 只按单标的决策，没有单日累计 / 重复下单间隔 / 跨标的敞口 | ⑤ 风控官新增账户级规则 |
| 5 | **"可复跑"只是事后工具** | `--log` / `--replay` 要人手动跑 | 新增 ⑥ 复核官：每次决策后自动比对 |

> ⚠️ 这 5 条里有 3 条**是我们自己写在局限里的**（`docs/34` 第 6 段、`docs/33` §5 的
> 「还想加什么」）。所以 v2 不是"再加几个 agent 显得热闹"，而是**把已知缺口补上**。

## 2. 逐角色规格

> 图例：**现有** = 已实现且可自检；**新增** = 本方案要做的

### 2.1 感知层（7 路）

| 角色 | 状态 | 输入（只读） | 输出 | 铁律 / 判据 |
|---|---|---|---|---|
| 📊 基差成本 `analyst_basis` | 现有 | `friction_budget.csv`、`funding_rates.csv` | verdict + conf 0.80 + 证据 | 净收益 + 资金费 > 3 bp → favorable；< 0 → unfavorable |
| 😱 情绪拥挤度 `analyst_sentiment` | 现有（**建议降级为可选**） | `funding_rates.csv` 费率结构 | verdict + conf **0.45** | 源（`bitget-signal`）44 源全空 → 置信度如实压低；**换可自采替代**：OI / 多空持仓比 / 主动买卖量 |
| 📰 事件新闻 `analyst_news` | 现有 | EDGAR 申报 / 官方 RSS / 财报日历 | severity + reason + conf | **reason 必须能回溯到标题**（v3 prompt + 代码强校验）；无来源 conf 封顶 0.40 |
| 📈 盘口与成交 `analyst_technical` | 现有 | `orderbook-*.csv`、`precise_fill_*.csv` | verdict + conf 0.70 + 证据 | 成交率 <10% 或 f_dmid < −3 bp → unfavorable |
| 🛡️ 执行风险 `analyst_execution_risk` | 现有 | 联合分布、`trades-*.csv` 最后成交、名义额 | **可证伪假设**列表 | 四要素：假设 + 实测量 + 阈值 + **证伪条件**；缺一即丢弃并留痕；最多 3 条进辩论 |
| 🔬 微观结构 `analyst_microstructure` | **新增** | 5 档盘口时序（同一 ts 的 bid/ask 深度差、档位变动） | 队列位置估计 + 撤单率 + 点差时序波动 | ⚠️ **不许把估计说成实测**：队列位置只能给区间 + 依据；给不出就进 `dropped` |
| ⏱️ 执行进度 `analyst_execution_progress` | **新增** | 本次挂单的成交进度 vs 预期分布 | 进度比 + 是否触发某条证伪条件 | ⚠️ 只报"该复核了"的**触发条件**，不产出数字、不建议价位 |

**共同铁律**：`validate()` 会作废"没有引用已实测的量"的结论；每路必须带 `sources`。

### 2.2 对抗层

| 项 | 说明 |
|---|---|
| 🐂 / 🐻 | 只引用与自己立场一致的结论；按**证伪条件分组**（同一证伪条件只出 1 条论点，防"一个判断换三个说法"） |
| ⚔️ 交叉质证 | 每方必须**指名对方最强的一条**并复述其证伪条件 —— 让"各说各话"在结构上不可能 |
| 裁决 | `得分 = Σ(置信度 × 证据强度)`；实测 1.00 / 外部可回溯 0.85 / 再计算 0.60 / 机制推断 0.30；差值 ≥0.25 才有倾向，否则 caution；方向自相矛盾 −0.15/条 |

### 2.3 事件闸门（LLM 的唯一职责）

| 项 | 说明 |
|---|---|
| 输入 | 候选标题（EDGAR 一手申报 / 官方 RSS / 财报日历 / 聚合 RSS），只认新鲜结果（默认 30 分钟内） |
| 输出 | `{is_event_window, severity, reason, confidence}` 严格 JSON |
| 降级 | 无 key / 调用失败 → 退化为确定性日历，并在输出里**如实标注"本次未使用 LLM"** |
| 事件驱动 | 无新条目 → 复用上次判定（带 TTL + 如实标注判定龄）；**新 EDGAR 重大申报 → 跳过缓存立即调** |
| 🔴 硬闸门 | 与确定性日历**取更严的一侧**；`block` → 挂单类方案直接作废（2026-09-19 修好的接线，见 `docs/46`） |

### 2.4 执行层

| 角色 | 状态 | 说明 |
|---|---|---|
| ✂️ 拆单规划器 `slice_planner` | **新增（确定性代码）** | 按**流动性自适应**：笔数由"单笔不超过首档深度 × 占比"与"可捕获名义额"共同决定；给出**时间表**（在窗口内铺开，而不是固定 `SLICE_USD`）。⚠️ 它产出数字，所以**必须**是确定性算法而不是 agent |
| 💰 交易员 `trader` | 现有 | 方式 = argmin(全挂单 / 现货挂+永续吃 / 全吃单)；规模 = min(请求, 可捕获名义额, 首档深度×25%)；价位 = 中价 ± 实测半幅点差。**不新造阈值、不做价格预测** |
| ⏱️ 执行进度官 | **新增** | 执行中按**证伪条件**监控（例如"报价恢复变动""成交进度低于 X 分位"），触发则提示：撤单 / 改价 / 追单 / 降级吃单。⚠️ 提示"该复核"，数字仍由确定性代码给 |

### 2.5 风控官（一票否决）

| 类别 | 状态 | 内容 |
|---|---|---|
| 固定规则 9 条 | 现有 | 事件窗口禁挂单 / 成本越线且边际不足 / 逆向选择过深 / **缺数据按最保守** / 停牌·报价冻结 … |
| agent 假设驱动规则 | 现有 | 由 `HYPOTHESIS_ACTIONS` 映射（日志里以 `agent:` 前缀标识）；**可真否决**（实测 `agent:stale_quotes` 驱动过 reject） |
| 账户级规则 | **新增** | 单日累计规模上限 / 同标的重复下单间隔 / 跨标的净敞口 |
| 留痕 | 现有 | 每条规则：引用什么 · 触发做什么 · **什么条件下撤销**；**未触发的也留** |

### 2.6 复核官（把"可复跑"进链路）

| 项 | 说明 |
|---|---|
| 触发 | 每次决策产出后自动 |
| 做什么 | 用本次日志的参数（含**冻结的 LLM 判定**）复跑一遍，按 `replay_check` 的契约投影比对 |
| 不一致时 | **降级 stand_down + 报警**（而不是照常下单） |
| 现状 | 参数、全部阈值、输入 SHA256、四层留痕、`decision_hash` 都已落盘 —— 只差"每次都自动比一遍" |

## 3. 三条设计红线怎么守（新增角色也不能破）

| # | 红线 | v2 的守法规矩 |
|---|---|---|
| 1 | **agent 不产出数字**（规模 / 价位 / 门槛） | 新增的 5 个角色里只有拆单规划器产出数字 → **因此它被放进"确定性代码"层，不算 agent**；微观结构给的队列位置只能是**区间 + 依据**，给不出就丢 |
| 2 | **agent 只收紧，不放松** | 新增角色一律**只能提假设 / 触发复核**，不能提"放大规模"；风控官的一票否决不可被推翻；单调性由 3 立场 × 3 闸门状态穷举自检保证 |
| 3 | **任何结论都要有实测量 + 证伪条件** | 微观结构 / 执行进度都必须给"看到什么就该撤回它"；给不出即进 `dropped` 并留痕 |

> 附加规矩：新增角色的 prompt 也要与事件闸门**同规格**——外置到 `prompts/`、
> 带版本号与 SHA256 指纹（现在只有事件闸门做到了，其余 prompt 仍内联）。

## 4. 落地顺序（按"补缺口的价值 ÷ 风险"排）

### P0 · 结构性缺口（不做，执行辅助就还是"只在下单前说话"）

| 步骤 | 交付物 | 验收（都要能自检） |
|---|---|---|
| P0-1 ⏱️ 执行进度官 | `analyst_execution_progress` + 一条 `agent:` 规则 + 前端"执行中"区块 | ① 构造"挂单未成交"的合成情形，断言它触发复核建议；② 构造"正常成交"情形，断言**不**报警（防它变成万能借口） |
| P0-2 🔬 微观结构分析师 | `analyst_microstructure` + 队列位置估计（区间） | ① 每条证据带 metric/value/source；② 队列位置给不出时进 `dropped` 并留痕；③ 断言它**不产出**任何规模/价位数字 |

### P1 · 可复跑强化

| 步骤 | 交付物 | 验收 |
|---|---|---|
| P1-1 ⑥ 复核官 | 决策后自动 `replay_check`；不一致 → 降级 + 报警 | 故意篡改一条规则 → 断言决策被降级为 stand_down 且报警字段为真 |
| P1-2 账户级规则 | 风控官新增 3 条规则 | 单日累计超限 / 重复下单间隔不足 → 各自触发对应 `hit` |

### P2 · 体验与自适应

| 步骤 | 交付物 | 验收 |
|---|---|---|
| P2-1 ✂️ 拆单规划器 | 自适应笔数 + 时间表 | 与固定 2000 USD 对比：在薄流动性标的上笔数**变多**、在厚流动性上**变少**；数字全部可复算 |
| P2-2 LUI 简报 | 一页人读简报（rationale / warnings / conditions） | 简报里每个数字都能点回代码常量或数据文件 |

## 5. ⚠️ 明确**不建议**加的东西（防止"多 agent 表演化"）

| 不要加 | 为什么 |
|---|---|
| ❌ 再加一个"决策 agent" | 会和风控官的"一票否决"打架；决策权必须留在确定性代码里 |
| ❌ 让任何 agent 产出数字（规模/价位/门槛） | 直接破红线 1，`--replay` 立刻失效 |
| ❌ "情绪 agent 接 LLM 讲故事" | 输入源 44 条全空，接了只能编 —— 现在如实压到 conf 0.45 是**正确**的做法 |
| ❌ 给辩论层再加"中立第三方裁决 agent" | 裁决现在是确定性代码，换成 agent 等于把可复跑性换成"看起来更民主" |
| ❌ 让 agent 决定"要不要撤单" | 撤单是执行动作，应由**证伪条件触发 + 确定性规则处置**；agent 只负责提条件 |

## 6. 与赛道三评审口径的对应（填表/路演时直接可用）

| 手册点名的能力 | v1 | v2 |
|---|---|---|
| **大单拆分** | 固定 2000 USD 粒度 | ✂️ 拆单规划器：按流动性自适应 + 时间表 |
| **盘口深度分析** | 5 档深度、首档约束 | 🔬 微观结构分析师：队列位置 / 撤单率 / 盘口不平衡 |
| **滑点模式调整** | 三方案成本对比 + 实测联合分布 | ⏱️ 执行进度官：执行中按实测偏差调整，而不是下完就不管 |
| **完整投研任务链路** | 5 路分析 → 辩论 → 闸门 → 交易员 → 风控 | 7 路 → 辩论 → 闸门 → 拆单/交易/进度 → 风控 → **复核** |
| **可访问 Demo + 录屏** | 页面单视图 | 页面新增"执行中"与"复核"两个区块，录屏 3 分钟能覆盖全链 |

## 7. 复跑命令（做完每一项都要能自己验一遍）

```powershell
python project2\agent_team.py --selfcheck        # 四层自检（含 LLM 闸门闭环 8 条断言）
python project2\agent_team.py --base NVDA --trader --log
python project2\agent_team.py --replay data\reports\debate-NVDA-<ts>.json
python run_p2.py --selftest                      # 全量 14 步
```

> 建议每加一个角色，就在 `--selfcheck` 里加**两条**断言：
> 一条证明它**能**改变决策（不是装饰），一条证明它**不会**在正常情形下乱报警
> （防它变成万能借口）——这是现有 `agent:stale_quotes` 一直在用的做法。
