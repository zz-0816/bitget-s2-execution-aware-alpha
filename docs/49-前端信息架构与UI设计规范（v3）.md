# 49 · 前端信息架构与 UI 设计规范（v3）

> 本轮做的不是"换个颜色"，而是**把 12 个平权面板重构成 4 个功能页 + 6 段决策链步进器**。
> 所有改动都落在 `web/` 三个文件里，页面逻辑与接口契约**一个字没变**，
> 因此可以直接用仓库自带的前端验收自检（⑬⑭⑮）复跑证明"没改坏"。

---

## 0. 一句话结论

| 指标 | 改版前（v2） | 改版后（v3） |
|------|--------------|--------------|
| 页面总高（1440×900 视口，跑完决策链） | **5040 px** | **2187 px**（−57%） |

| 切到别的页面后还知道这单结论吗 | 不适用（只有一页） | 顶栏常驻裁决胶囊（`NVDA · 不参与 ｜ 0 USD`） |

## 1. 改版前诊断（按八大维度，附实测）

诊断不是"看着乱"，下面每条都有实测数字或可复现的操作。

### 🔴 严重问题（Must Fix）

**1. 信息架构缺失 —— 12 个面板纵向平铺，无导航、无分组**
`web/index.html` 的 `<main>` 里是 12 个 `.panel` 直接平铺：决策链 / 五路分析 / 辩论 / 闸门 /
交易员 / 风控官 / 执行进度官 / 成本分布 / 溯源 / 概览表 / 阈值表 / 数据边界。
实测 `body_h = 5040px`（1440×900 视口，约 5.6 屏）。
后果：① 用户不知道系统共有几块能力；② 想比较"链路上哪一段把结论压下来了"必须来回滚；
③ 想跳到"阈值表"只能手动拖滚动条。

**2. 视觉层次平权 —— 产品的重点（决策链）与参考数据（阈值表）长得一模一样**
12 个面板统一 `--surface` 底 + 同尺寸标题（16px）+ 同圆角。页面上没有第二级标题，
`<h1>` 之后直接是 12 个同级 `<h2>`，读者 3 秒内无法判断"哪个是结论、哪个是附录"。

**3. 运行区与结果区混在一条流里**
「跑完整决策链」按钮在第 1 屏，而它产出的「交易员 / 风控官」在第 5~6 屏。
点完按钮后必须往下滚很久才看得到结果，且中途会经过"尚未运行"的空面板。

### 🟡 建议改进（Should Fix）

**4. 空态文案不统一**：决策链面板写「尚未运行」，概览表/阈值表/数据边界写「加载中…」，
两类语义（"没跑" vs "在加载"）用了同一种灰字，读者分不清是"要我等"还是"要我点"。

**5. 概览表等待期无反馈**：`/api/overview` 要串行跑 10 个标的（实测约 10.3 秒），
等待期间表格只有一行「加载中…」，没有骨架屏、没有进度感。

**6. 顶栏信息与页面状态脱节**：顶栏显示了快照时间/基准时间/LLM/标的数，
唯独没有**当前这一单的结论** —— 那才是用户最关心的一个值。

### 🟢 锦上添花（Nice to Have）

**7. 无键盘级导航**：只有 `skip-link`，没有 landmark 级的"跳到某个功能区"。
**8. 无深链**：所有状态都在内存里，刷新即回到默认，无法分享"我要给你看阈值表"。

## 2. 新信息架构（IA）

```
执行决策台（单页应用，4 个功能页）
│
├─ 顶栏（sticky，不随功能页变化）
│   ● 服务状态 │ 执行决策台 · 副标题 │ [常驻裁决胶囊] │ 快照 · 基准 · LLM · 标的
│
├─ ◉ 决策台                              ← 默认页
│   ├─ 页头（页标题 22px + 一段说明 13px）
│   ├─ 运行控制面板      [标的 chips] [名义额] [跑完整决策链] [刷新全标的概览]
│   ├─ 裁决条（verdict bar）  立场 / 规模 / 为什么 / 单调性校验
│   ├─ 决策链步进器（6 段，横排，可点可键盘）
│   │    ① 五路独立分析 → ② 多空辩论 → ③ 事件闸门 → ④ 交易员 → ⑤ 风控官 → ⑥ 最终决策
│   └─ 详情区（只显示步进器选中的那一段，6 选 1）
│
├─ ⏱ 执行闭环
│   ├─ ⑥ 执行进度官（在途持仓切换 + 结论 + 实测量 + 处置口径 + 留痕）
│   └─ 成本与联合成交分布
│
├─ ▦ 全标的概览
│   └─ 10 个标的横向对比表（点标的名 → 跳回决策台并重跑）
│
└─ ⚖ 可信度
    ├─ 生效阈值与来源
    ├─ 可复跑溯源（decision_hash + 输入 SHA256）
    └─ 数据边界（SNAPSHOT.md 原文）
```

**为什么这样分？** 分组的依据是"读者带着什么问题来"：

| 功能页 | 读者的问题 |
|--------|-----------|
| 决策台 | 这一单该不该做？为什么？链路上哪一段决定的？ |
| 执行闭环 | 已经下了的单，现在有风险吗？该怎么处置？ |
| 全标的概览 | 这 10 个标的横向比，哪个更值得做？ |
| 可信度 | 这些数字凭什么可信？能复跑吗？边界在哪？ |

**为什么决策链用"步进器 + 单段详情"而不是"6 个面板继续平铺"？**
因为这条链是**串联**的（5 路分析 → 辩论 → 闸门 → 交易员 → 风控 → 最终），
读者同一时刻只需要看其中一段。同时步进器把 6 段的**结论**横排在一行，
"整条链有没有卡住、卡在哪一段"一屏可见 —— 这比 6 个面板竖着铺开更省视线，也更能表达"链"。

> 详情面板**始终留在 DOM 里**（只是切换 `hidden`），所以：
> ① 段与段之间切换不用重新请求、不用重渲染，点一下就是瞬时的；
> ② 仓库自带的渲染冒烟（`tools/web_render_check.js`）里 9 个区块照样全部验收。

## 3. 设计系统

### 3.1 Token（沿用 v2 的色阶，新增布局 token）

色阶继续用 Radix Colors 的 12 级深色语义（`--s1..--s12` 中性 / `--b1..--b12` 强调 /
`--r* --a* --g*` 语义色），并对齐 Open Props 的 4px 间距刻度。

v3 新增：

```css
--nav-w: 232px;   /* 侧栏宽度 */
--top-h: 58px;    /* 顶栏高度（侧栏 sticky 定位要用） */
--maxw:  1400px;  /* 内容最大宽（v2 是 1320，v3 要容纳侧栏 + 主区） */
```

### 3.2 层级（这是 v3 的核心修复）

| 层级 | 元素 | 字号 | 字重 | 说明 |
|------|------|------|------|------|
| L0 | 产品名 | 18px | 700 | 顶栏 |
| L1 | **页标题** `.pane-title` | **22px** | 700 | 一屏只有一个 |
| L2 | 区块标题 `.panel-title` | 16px | 600 | 带 3px 蓝色序号条 |
| L2.5 | 裁决数字 `.stance` | 27px | 700 | 数据即标题 |
| L3 | 正文 / 表格 | 13–14px | 400–500 | |
| L4 | 辅助说明 `.hint` | 12px | 400 | `--text-faint` |
| L5 | 标签 / 脚注 `.mono-dim` | 11px | 400 | |

**v2 的毛病是 L1 缺失**（`<h1>` 之后全是 16px 的 `<h2>`）。
v3 补上 22px 页标题 + 13px 页说明，页面第一次有了"这是哪一页、这一页干什么"的开头。

### 3.3 间距与圆角

沿用 4px 刻度（`--sp-1..--sp-8` = 4/8/12/16/24/32/48/64）。
圆角分档：`--r-sm` 6px（卡片内元素、按钮）/ `--r-md` 10px（面板）/ `--r-pill` 999px（胶囊、chip）。

### 3.4 布局

```css
.app {
  display: grid;
  grid-template-columns: var(--nav-w) minmax(0, 1fr);   /* ← minmax(0,1fr) 必须有 */
  gap: var(--sp-5);
  align-items: start;
}
.app-nav { position: sticky; top: calc(var(--top-h) + var(--sp-3)); }
```

⚠️ `minmax(0, 1fr)` 不是写法偏好：默认的 `1fr` 是 `minmax(auto, 1fr)`，
内容里有宽表格时**主区会被撑破**，正是 v2 那种"关键列被推到屏幕外"的成因。
`minmax(0, 1fr)` 允许主区收缩到 0，配合内层 `.table-wrap { overflow-x: auto }` 把滚动收在表格内部。

## 4. 静态设计规格（各页布局）

### 4.1 顶栏（`.top`）
`sticky top:0`，一行 flex：品牌（呼吸灯 + 标题 + 副标题）→ **裁决胶囊** →
会话元信息（快照 / 基准 / LLM / 标的）。
裁决胶囊 `margin-left:auto` 把它推到中右侧，`data-st` 决定颜色（绿/黄/红），
功能页切来切去它一直在 —— 这是 v3 解决"切页丢上下文"的方案。

### 4.2 侧栏（`.app-nav`）
桌面（>1080px）：竖向列表，`sticky` 跟随滚动。每项 = SVG 图标 + 主标签 + 一行说明。
选中项：`--surface-2` 底 + `--line` 边框 + 左侧 3px 蓝色强调条。

### 4.3 决策链步进器（`.stages` / `.stage`）
横向 flex + `overflow-x:auto`，每段 `<button class="stage" role="tab">`：

```
┌──────────────────────┐
│ ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔  │ ← ::before 顶部状态条（绿/黄/红）
│ ① 五路独立分析    ● │ ← .s-name + .s-dot（data-st 定色）
│ 可执行               │ ← .s-stance（沿用 s-proceed/s-caution/s-stand_down）
│ 6 份报告，6 份有效    │ ← .s-detail（JS 侧截断到 88 字，title 里给全文）
└──────────────────────┘
```

选中项加 `is-on`：蓝色边框 + `inset` 内描边 + 抬高上的背景。

### 4.4 详情区（`.detail` / `.detail-panel`）
6 个面板依次排列，只显示一个。切换时 `detail-in` 动画（淡入 + 上浮 6px）。

### 4.5 状态色映射（沿用 v2，未改）

| 语义 | 常量 | 用途 |
|------|------|------|
| 可执行 | `--ok` `--ok-bg` `--ok-line` | 裁决条 / 步进器状态点 |
| 谨慎执行 | `--warn` `--warn-bg` `--warn-line` | 同上 |
| 不参与 | `--danger` `--danger-bg` `--danger-line` | 同上 |

## 5. 动态设计规格（动效与交互）

**总开关**：`:root { --m: 1 }`，`prefers-reduced-motion: reduce` 时置 0，
所有时长都写成 `calc(… * var(--m))`，一个变量关掉全站动效。

| # | 交互 | 触发 | 效果 | 时长 / 曲线 |
|---|------|------|------|-------------|
| 1 | 功能页切换 | 点侧栏 / 深链 | 页整体淡入 + 上浮 6px；页内区块 60ms 步进错落入场 | 260ms / `--ease-out-3`；子块 420ms |
| 2 | 步进器选中 | 点某段 | 详情区淡入上浮；该段加 `is-on` | 260ms / `--ease-out-3` |
| 3 | 侧栏选中条 | 切换功能页 | 左侧强调条 `scaleY(.3) → 1` | 260ms / `--ease-out-3` |
| 4 | 裁决条出现 | 决策链跑完 | 淡入 + 轻微缩放（`scale(.995)`） | 420ms / `--ease-out-3` |
| 5 | 成本条形生长 | 面板渲染 | 宽度 0 → 目标值（**先渲染 0、下一帧再赋值**，否则 transition 不触发） | 420ms / `--ease-out-3` |
| 6 | 概览表数值变更 | 刷新概览 | 变了的行闪一次底色 | 900ms |
| 7 | 概览表加载 | 点刷新 | 6×6 骨架屏流光 | 1.4s 循环 |
| 8 | 存活指示灯 | 常驻 | 呼吸脉冲（异常时 1.2s 快闪） | 2.4s 循环 |
| 9 | 告警弹窗 | `/api/alerts` 有新条目 | 从右侧滑入 + 闪烁 3 次 | 420ms / `--ease-spring` |
| 10 | hover / focus | 鼠标 / 键盘 | 卡片上浮 1–2px；`:focus-visible` 出 2px 焦点环 | 120–180ms |

**键盘可达性**：
- 侧栏：`Tab` 顺序即为视觉顺序；`↑/↓` 在导航项之间移动焦点。
- 步进器：`←/→` 切换段落并同步切换详情面板（roving focus）。
- 所有可点元素都是原生 `<button>`，Enter/Space 天然可用。
- 页面第一个可聚焦元素仍是 `skip-link`（跳到主内容）。

**深链**：切换功能页时 `history.replaceState` 把 `#pane-decision` / `#pane-exec` /
`#pane-overview` / `#pane-trust` 写进地址栏；带 hash 打开页面时 `initShell()` 直接落到那一页。
（`file://` 下 `replaceState` 可能被拒，已包 `try/catch`，失败不影响切页。）

## 6. 无障碍

| 项 | 做法 |
|----|------|
| 对比度 | 12 组语义配色全部按 WCAG AA 复算，最低 **5.74**（`--on-accent` on `--accent`） |
| 减少动效 | `prefers-reduced-motion` → `--m: 0`，全站动效归零 |
| 焦点可见 | `:focus-visible` → 2px 焦点环（`--ring`），鼠标点击不显示 |
| 语义化 | `<header>` / `<nav aria-label>` / `<main id="main">` / `<section role="region" aria-label>` / `<footer>`；页面一屏一个 `<h2>` 页标题，区块用 `h2`，无跳级 |
| ARIA | 步进器 `role="tablist"` + `role="tab"` + `aria-selected` + `aria-controls`；详情面板 `role="tabpanel"`；裁决胶囊 `role="status" aria-live="polite"`；运行态 `role="status"` |
| 触摸目标 | `.chip` / `.btn` / `.stage` / `.nav-item` 最小高度均 ≥ 32px，步进器段高约 100px |
| 语义化按钮 | 标的 chip 从 `<span onclick>` 改为 `<button>`（原来键盘不可达） |

## 8. 顺带修掉的三个既有缺陷

改版过程中，前面几层验收把三个**一直存在但从未被发现**的问题暴露了出来。
它们都不是"改版改坏的"，而是"以前的自检看不见"。

### 8.1 页面把后端写的 markdown 原样显示成星号

后端在若干字段里写的是 markdown（例：合成演示持仓的字样写成 `**合成演示持仓**（非真实下单）`），
而前端在这些位置用的是 `esc()`（纯转义），于是页面上直接出现 `**`。
真浏览器探针实测默认页有 **14 处**字面 `**`。

**为什么以前是绿的**：本机被用来跑自检的那个 Python 缺少 tzdata，
决策链一开跑就抛 `ZoneInfoNotFoundError`，页面根本没渲染出内容 —— 
一个区块都没渲染，字面标记自然是 0 处，检查也就"通过"了。

**修法**：把这些"数据文本"字段统一改走 `mdInline()`（渲染 markdown），
`title` 属性这种必须纯文本的地方走 `plain()`（剥掉标记）。
涉及 `renderAnalysts` / `renderGate` / `renderTrader` / `renderRisk` /
`renderExecProg` / `renderOverview` / `renderFinalPlan`。
属性位（`class=` / `data-*` / `title=`）保持 `esc()` 不变。

### 8.2 「全标的概览表」从来没有被真正验证过

`tools/web_render_check.js` 的夹具匹配是"精确 → 参数子集 → 路径"三层。
但夹具是按**路径**存的（`/api/overview`），而页面一定会带参数
（`/api/overview?qty=5000`）；参数子集那一层要求夹具键**自己也带** `?`，于是直接 `return null` → 404。
页面渲染出 `加载失败：no fixture …`（实测该单元格只有 **86 字符**），
而检查只拦 `undefined` / `NaN` / `加载中` / `尚未运行` —— **一个从未渲染成功的区块被判成通过**。

**修法**：`matchFixture()` 末尾补一层"同路径夹具兜底"。
修完概览表渲染出 **6140 字符**，第一次被真正验证。
（参数化的端点用同一份夹具近似即可 —— 这一步验证的是"这一块有没有渲染出来"，
不是参数的逐字精确性。）

### 8.3 概览表没有加载反馈

`/api/overview` 串行跑 10 个标的（约 10.3 秒），等待期只有一行灰字。
**修法**：请求发出前先铺 6×6 骨架屏（`.skeleton` 流光），加载完再替换成真实行。

## 11. 追加改动：可读性精简（按反馈）

### 11.1 证据文件路径：从"每行都挂"改成"折叠备注"

**问题**（反馈原话：*有点冗余且这个页面太长*）：
`renderAnalysts` 原来在每条证据行尾都挂一个文件路径（`· 现货半幅点差 = 1.14 bp  ← data/derived/friction_budget.csv`），
再在卡片底部拼一整行 `a-src`。一张卡 5~10 条证据 → 5~10 个路径，
`news` 那种 10 条证据的卡片被撑到近 400px 高，而路径几乎没人看。

**改法**：证据行只留 `指标 = 值`；卡片底部加一个原生 `<details>`：

```
▸ 证据来源（5 条）          ← 默认收起
┌ 展开后
│ 现货半幅点差 → data/derived/friction_budget.csv
│ 往返净收益（全挂单）→ data/derived/friction_budget.csv
│ 48h 窗口资金费收入 → data/derived/funding_rates.csv
│ 双腿最优执行成本 → project2/execution_cost.py
└
```

**为什么是折叠而不是删除**：项目底线是"页面上每个数字都能点回代码常量或数据文件"，
删掉就破了这条。折叠同时满足"默认不占版面"和"溯源随时可查"。
保留 `指标 → 文件` 的对应关系（不是只丢一个去重后的文件列表），
所以"这一条数字从哪来"仍然逐条可查。

用原生 `<details>` 而不是自定义 JS 折叠：键盘可达、默认无障碍语义、
不引入任何状态管理代码。

**真浏览器实测**（探针）：收起时 `open:false` / `summary="证据来源（5 条）"`；
点 summary 后 `open:true`，列表 5 条可见。

### 11.2 概览「条件」列：从契约字段名改成大白话

**问题**（反馈原话：*我认为可以直接按大白话来讲而不是直接调用 price_band_bp 这种*）：
后端 `conditions` 直接给的是契约键名，页面原样拼成一行：

```
price_band_bp=0.46; size_usd=5000; timing=仅在 route=in_house 时挂单; stockroute 期间挂单不省点差
```

三个变量名 + `route=in_house` + `stockroute`，读者得先学一遍内部术语。

**改法**：在 `app.js` 加一层**纯显示层**映射（`COND_LABEL` + `condText()` + `plainToken()`），
**接口字段一个不动** —— `run_record` / 表单稿引用的是原始键名，改了会破坏可复跑契约。
值里的技术词也一起翻（`route=in_house` → 内部撮合，`stockroute` → 外部股票路由）。

| 键 | 改前显示 | 改后显示 |
|----|----------|----------|
| `price_band_bp` | `price_band_bp=0.46` | 现货点差 0.46 bp（挂单赚不回它，就等于白付一次手续费） |
| `size_usd` | `size_usd=5000` | 单笔规模 不超过 5000 USD |
| `timing` | `timing=仅在 route=in_house 时挂单; stockroute 期间挂单不省点差` | 挂单时机 仅在内部撮合时挂单；外部股票路由期间挂单不省点差 |

一条一行（`·` 项目符号），而不是用 `;` 挤成一段。**未知键不隐藏** ——
回退成"键名去下划线 + 原值"，宁可丑一点也不吞信息（后端加字段时不会静默丢内容）。

顺带把「执行闭环」里同类的 `route / session` 一行也翻了（→ `撮合路由 / 交易时段`）。
