# 50 · 后续新增标的：完整操作清单

> 本文回答一个具体问题：**以后想加标的，要动哪些地方？**
> 全部条目都在本机代码里核对过（含隔壁项目一仓库 `D:\bitgetS2_factory_trading`），
> 不是推测。凡"不改会静默出错"的地方都单独标了 ⚠️。

---

## 0. 一句话结论

**前端零改动**（chips 由 `/api/health` 数据驱动）；要改的是**采集、派生、搬运、消费、冻结清单**五层，
其中 **`CORE_PAIRS` 在项目一里有 5 份重复的字面量**，而 **`run_p2.py::_bases()` 那层过滤会把新标的静默丢掉** ——
这两处是"想加就一定会踩"的坑。

---

| # | 层 | 位置 | 改动 | 不改会怎样 |

## 2. 第 1 层：采集（项目一，必须手改）

### 2.1 `CORE_PAIRS` 散落在 5 个文件里（**没有共享模块**）

```
build_panel.py:49
kline_accumulator.py:80
tools/data_integrity.py:31
tools/export_basis_series.py:38
（以及 spread_sampler.py / orderbook_sampler.py / trades_sampler.py 引用的同一份清单）
```

配对形式是**两个符号成对**：

```python
("RTSLAUSDT", "TSLAUSDT")   # 现货 rToken 前有 R 前缀，永续没有
```

**加之前先确认这个配对真的可用**：`data/universe.csv` 里该行 `has_spot=True`。
现在 `has_spot=False` 的有 108 个（321 永续 − 213 可用配对），**没有现货腿就不成立双腿策略**。

### 2.2 ⚠️ 两个硬约束

1. **采样器有单实例锁**（`spread_sampler.py` 等各自持锁 + 守护进程自锁）→
   改完必须**重启守护进程**才生效，光改文件不会自动重载。
2. **盘口不可回补。** 交易所不提供 bid/ask 历史接口 —— 新标的**从加入的那一刻起**才有数据，
   历史缺口**永远补不回来**。而基差半衰期只有约 6 分钟，
   所以新标的想进入"时间序列密"这个卖点，需要**重新累积几天**。
   → 这意味着"加标的"不是改配置，而是**一次新的采样周期**。

## 3. 第 2 层：派生数据重算（不用改代码）

这 5 个脚本的标的集合都是**从数据里自动推导**的，不是写死的：

```python
bases = sorted(set(spot) & set(perp))     # friction_budget.py:105
bases = sorted(set(snap_s) & set(snap_p))  # joint_fill_analysis.py:400
```

所以新数据的盘口/成交到位后，直接重跑即可（参数以 `--help` 为准）：

| 脚本 | 产出 | 实测参数 |
|------|------|---------|
| `tools/friction_budget.py` | `friction_budget.csv` | `--k`（逆向选择 horizon，默认 6）、`--fee-spot` 等费率 |
| `tools/funding_analysis.py` | `funding_rates.csv` | `--pages`、`--days`、`--window-hours`（默认 48） |

| `tools/joint_fill_check.py` | `joint_fill_check_in_house.csv` | —— |
| `tools/threshold_calibration.py` | `threshold_calibration.json` | —— |

> **注意一个现成的例子**：现在 `friction_budget.csv` / `joint_fill_all*.csv` / `precise_fill_spot_bid.csv`
> 只有 **9 行**，缺 **SOXL** —— 因为 SOXL 的现货是死报价（bid/ask 冻结 15 小时，

## 5. 第 4 层：搬运快照（项目一 → 项目二）


## 6. 第 5 层：项目二消费侧

### 6.1 `run_p2.py::DEFAULT_BASES`（第 65 行）
加标的进清单。

### 6.2 ⚠️ `run_p2.py::_bases()`（第 110 行）—— **必须一起改**

```python
return [b for b in DEFAULT_BASES if b in got] or got or list(DEFAULT_BASES)
```

它优先返回 **`DEFAULT_BASES` ∩ 实读**。新标的如果**只加进了数据、忘了加 `DEFAULT_BASES`**，
就会被这层交集**静默丢掉**（页面少一行，接口不报错，`--selftest` 也不会红）。

建议改成"实读优先，`DEFAULT_BASES` 只负责排序"，这样数据里有什么就显示什么：

```python
order = {b: i for i, b in enumerate(DEFAULT_BASES)}
return sorted(got, key=lambda b: (order.get(b, len(DEFAULT_BASES)), b))
```

### 6.3 `project2/events_calendar.json`
`earnings` 下加该标的的财报日。**ETF / 无财报的也要加空数组**（现在 `SPY` / `QQQ` / `SOXL` 就是 `[]`）——
因为文件自己的 `_README` 写得很清楚：

> static 模式的覆盖度完全取决于本文件质量 —— **日历空 = 闸门空**。
> 过期日历比没有日历更危险（会给出虚假的'无事件'）。

新标的漏了这一步，事件闸门会对它**永远报"无事件"**，而这是硬门禁依据。
顺手把 `source` 字段填上（现在所有条目都没 source，所以置信度被压到 0.40，文件里注明"这是如实状态"）。

### 6.4 `project2/signal_adapter.py`
里面有"与核心标的无关的行业噪音"关键词表（第 366 行附近），加标的时要补该标的的相关词，
否则它的新闻会被当噪音滤掉。

### 6.5 前端 —— **不用改**
`selectBase()` 直接渲染 `/api/health` 返回的 `bases`，chips 数量自动跟着变。
`web/index.html` 里也没有任何写死的标的。

## 7. 第 6 层：冻结清单重生成

`friction_budget.csv` / `funding_rates.csv` / `joint_fill_*.csv` / `orderbook-*.csv` / `trades-*.csv`…
**全部是 `FROZEN` 类别，SHA256 逐字节核验**（`tools/snapshot_manifest.py` 的 `SPEC`）。
数据一变，`--verify` 必红。所以：

```bash
python tools/snapshot_manifest.py            # 无参数 = 重新生成 data/SNAPSHOT.md
python tools/snapshot_manifest.py --verify    # 必须通过（冻结项逐字节一致）
```

## 9. 两种改动幅度，别搞混

| 目标 | 要做的事 | 大概成本 |
|------|---------|---------|
| **只想让页面多一个标的**（演示用，不重采样） | 项目二内：`DEFAULT_BASES` + `_bases()` + `events_calendar.json` → 重生成 SNAPSHOT.md → 复跑自检。数据得是**已有的**（比如从项目一的 `universe-*.csv` 里挑） | 小时级 |
| **真的把它纳入策略** | 走完 §2 → §8 全部 | **跨天的采样周期**（盘口不可回补，要重新累积） |

## 10. 顺带建议：把"核心 10"变成"可复算的前 10"

现在 `CORE_PAIRS` 是 5 份手写字面量，**没有任何成文筛选依据**，
而项目一自己的 `docs/06` 写着"顺带发现流动性更好的标的（**此前只盯 10 个**，池子开大了）"——
即先定名单、后枚举全集。评委若问"为什么是这 10 个"，现有材料答不上。

`data/universe.csv` 已经带齐字段（`spot_vol24h_usdt` / `perp_vol24h_usdt` / `perp_spread_bp` /
`perp_bid_depth_usd` / `perp_ask_depth_usd`），完全可以做一次**可复算的筛选**，
例如"两边 24h 成交额都进前 30、且永续点差 < 1 bp"，让任何人都能重跑复现。
那样"加标的"就从"改 5 处字面量"变成"改一个筛选口径"，也顺手把重复定义消掉。
