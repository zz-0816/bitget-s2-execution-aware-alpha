# 51 · 怎么用（小白版）· 什么时候能交易 · 什么时候该离场

>
> 这一页只回答四个问题：**我怎么用** / **什么时候能交易** / **交易后什么时候离场** /
> **这个项目需要离场规则吗**。最后一个问题的答案有一半是「不需要」，如实写在第 4 节。

---

## 0. 先记住一句话

**这个项目不替你下单，它替你「把该看的都看了，并且说清凭什么」。**
你从页面上拿到的永远是一句话 + 一串能点回去的证据，不是一张成交回报。

---

## 1. 三步上手（真的只有三步）

### 第一步 · 确认环境（一次就够，约 1 分钟）

```powershell
python run_p2.py --selftest        # 期望：17 步全部通过、退出码 0
```

不需要网络、不需要 API key。看到 `全量自检通过` 就可以往下走了。
（配了 LLM key 的话再跑一次 `--selftest --net`，多看两步。）

### 第二步 · 跑一次决策，**只看「最终立场」这一格**

```powershell
python run_p2.py            # 起服务，浏览器开 http://127.0.0.1:8788
```

页面上：点一个标的 → 填名义额 → 点「跑完整决策链」。约 2–3 秒后看**最上面那条**：

| 你看到的 | 意思 | 你该做什么 |
|---|---|---|
| 🟢 **可执行** `proceed` | 三道关都过了，可以按下面给的方案做 | 看「④ 交易员」那一段：方式 / 规模 / 价位 / 拆几笔 |
| 🟡 **谨慎执行** `caution` | 能做，但有条件（通常是辩论僵持或成本贴着门槛） | 按提示**缩小规模**或**放宽价位**，别按原样做 |
| 🔴 **不参与** `stand_down` | 这一单**不该做** | 别做。往下看「为什么」——那一栏会指名是哪一级拦下的 |

> ⚠️ 只有这一格决定「做 / 不做」。下面五个面板是**为什么**，不是**再投一次票**。

### 第三步 · 真的有持仓时，才看「执行闭环」页

这一步**需要你提供在途持仓单**（本项目不接交易所、不知道你手上有啥）：

```jsonc
// data/positions/open.json   ← 你自己写，本服务只读不写
{ "positions": [
    { "id": "p1", "base": "NVDA", "qty_usd": 500,
      "spot_filled": true, "perp_filled": false,   // ← 决定有没有裸露敞口
      "opened_ms": 1789802276375 }
] }
```

没有这个文件时，那一页会明确写「无在途订单」——**它不会画绿灯**。
（想看这个功能长什么样：把页面上「在途持仓」切到「合成演示单」，
它带 `synthetic` 标记，页面会显眼标注**这不是真实下单记录**。）

## 2. 什么时候能交易？—— 答案很具体

**看「最终立场」这一格。** 它是整条链唯一决定做不做的地方，而且是**单调收紧**的：
后面每一级只能把它改得更保守，永远不能改回来。

三道关，任何一道不过就是「不参与」：

| 关 | 判据（都能点回代码常量） | 不过会怎样 |
|---|---|---|
| ① 事件闸门 | 确定性日历 **与** LLM 事件判定，取**更保守**的一侧 | `block` → 挂单类方案直接作废，只剩吃单；再被风控否决就归零 |
| ② 多空辩论 | 多头领先 ≥ `0.25` → 可执行；空头领先 ≥ `0.25` → 不参与；**分差 < 0.25 = 僵持 → 谨慎执行** | 不参与，交易员不下单 |
| ③ 风控官 | 9 条固定规则 + agent 提出的风险假设（`veto` 级一票否决） | 规模归零 |

另外还有一条**很容易被忽略**的：规模被 `min(你请求的, 可捕获名义额, 首档深度 × 25%)`
夹住后，如果**低于 100 USD**，正确结论也是「不做」——
不是「拿 37 USD 去做一笔套利」。实测里 NVDA 就是这样被拦下的。

### 现在 10 个标的为什么**都**是不参与？

先说一个**我自己造成的**原因，已经修掉了：

> 我早先把「在途持仓」下拉框的第一项设成了**合成演示单**，
> 而 HTML 的第一个 option 就是默认值。于是**每次跑任何标的**都会带上
> 「现货腿已成交、永续腿未成交」的合成持仓 → 执行进度官判**裸露敞口** →
> 一票否决 → 永远「不参与」。而且它优先级最高，把真实原因也盖住了。
> **演示数据绝不能是默认值** —— 现在默认是 `auto`（读你的真实持仓单，没有就不带）。

关掉它之后，10 个标的**仍然都不参与**，但原因各不相同（实测，名义额 500 USD）：

| 标的 | 真实原因 |
|---|---|
| NVDA / QQQ | 可执行规模被首档深度压到 **37–38 USD**，低于 100 USD 下限 → 不做 |
| TSLA / SPY / MRVL | `agent:stale_quotes` + `agent:quote_frozen`（现货腿长时间零成交、报价冻结）+ 逆向选择 |
| AAPL | `gate_block`（事件闸门判了 block） |
| META | `debate_stand_down`（辩论层不参与）+ 现货腿停滞 |
| GOOGL / HOOD | `adverse_selection`（逆向选择为负）+ 报价冻结 |
| SOXL | `leg_risk_high`（腿风险高）→ 收紧规模 |

**根子上是一件事**：现货腿自 **09-14** 起零成交（报价还在、成交是死的）——
见 `docs/29`。这不是程序坏了，是**如实反应市场状态**。

### 结论会变吗？会。

实测同一台机器、相隔几分钟，NVDA 的辩论裁决从 `stand_down` 变成 `proceed`
（因为事件层的实时标题变了：从 FOMC 宏观标题换成 AAPL 自己的申报）。
这是**设计如此**：事件是活输入，有 30 分钟 TTL 缓存、新 EDGAR 申报立即重判。
所以页面上永远显示**决策基准时间**（`basis=asof` 还是 `wallclock`）——
不知道「这是按几点的数据判的」，结论就没有意义。

## 3. 交易后什么时候离场？—— 本项目**不给离场时点**

这是必须说清楚的一段。

本项目在「下单之后」提供两样东西，**都是告警，不是离场指令**：

| 谁 | 什么时候响 | 响了你该做什么 |
|---|---|---|
| ⏱️ **执行进度官** | ① 只成交一条腿（>`NAKED_GRACE_MIN=1` 分钟）→ **否决级**<br>② 挂单 ≥ `STALE_TRADE_MIN=30` 分钟且这条腿零成交 → 警示级 | ① 二选一：立刻吃单补上另一腿 **或** 平掉已成交的那条腿（两者都付一次往返成本）；在此之前不开新仓<br>② 复核执行方式：改价 / 撤单 / 转双腿全吃单 |
| 🛡️ **持仓期巡检** | ① 裸露敞口 ② 事件翻脸（持仓期间判出 `block`） ③ 逆向选择加深 ④ 行情停滞 | 提示「该复核了」；**critical** 级走右下角闪烁弹窗 |

**它们不说「平在什么价」，也不说「现在该不该止盈止损」。** 原因不是偷懒：

1. 本项目**不下单**，因此**没有成交价、没有持仓成本、没有持有期损益口径**；
2. 没有这三样，任何「离场价」都是**编出来的数字**——而这个项目最不能接受的
   就是编数字（红线：agent 不产出任何价格/规模）。

所以「什么时候离场」这个问题，本项目的回答只能是：
**「什么时候该复核」它答，。「平在什么价」它不答。**

## 4. 这个项目需要离场规则吗？

**分两种用法，答案不同：**

| 你的用法 | 需要吗 | 为什么 |
|---|---|---|
| 按赛道三「AI Trading Desk · 执行辅助」提交 | **不需要** | 手册点名要的是「拆单 + 盘口深度分析 + 滑点管理」。这三样本项目都有，且都可复跑；离场属于持仓管理，不在这个子题的范围内 |
| 当成一个**能实盘的完整交易系统**用 | **需要，而且现在缺** | 没有离场规则 = 只有入场没有出场。要补的话，缺的不只是规则，而是**数据**：需要真实的成交回报与持仓成本，才能算持有期损益 —— 本项目当前的数据管线**没有这一环** |

**要补的话，最小可行的一步是**（不是承诺，是路线）：

1. 先把 `data/positions/open.json` 变成**真实成交回填**（现在是你手写）；
2. 用真实成交价算出「持仓成本 + 已付摩擦」（这一步是纯确定性算术，不需要 agent）；
3. 再定离场判据 —— 而且必须是**可证伪**的，例如
   「若价差收敛到 X bp 以内 / 若逆向选择连续 N 分钟为正 / 若事件闸门转 `block`」；
4. 这些都做完，才谈得上「离场价」。

> ⚠️ 顺带一条：`docs/47` 里的 v2 分工图已经把「复核官」列为**规划中**的角色。
> 本文说的离场能力，和那个是同一件事 —— **现在都还没做**。

## 5. 这一轮顺手修掉的三个真问题

| # | 问题 | 怎么发现的 | 现在怎么防回退 |
|---|---|---|---|
| 1 | 「在途持仓」默认是**合成演示单** → 每个标的都带裸露敞口 veto，且盖住真实原因 | 你截图问「为什么一直是不参与」，逐条比对三种模式 | 默认改 `auto`；渲染冒烟断言「第一个 option 必须是 auto」 |
| 2 | 理由栏只写**排在最前**的那条 veto，把真实市场原因藏了 | 同上：截图里写 `agent:partial_fill_naked`，而 `debate_stand_down` 不见了 | 多条触发规则时全部列出，并提示「共 N 条」；冒烟里有对应断言 |
| 3 | 概览表「条件」列**每行原文一模一样**，4 行吃掉半个屏幕 | 你的截图（同一段字重复 4 遍） | 行内只留**差异化数值**，通用口径提到表下**只写一次**；列显隐做成 chips（多选、状态持久化）；点行展开看全文 |

第 3 条的具体样子：概览表现在默认只显示 **标的 / 风险 / 结论 / 事件** 四列，
「理由」「条件」用上方的 chip 打开；条件行变成
`0.46 bp → 需覆盖 0.23 bp ｜ ≤ 500 USD ｜ 仅在内盘撮合时挂单`，
而「挂单赚不回点差就等于白付一次手续费」这类通用解释只在表下的
「条件怎么读」里出现一次。**收起不等于删掉** —— 控件行会写明"已收起 N 列"，
点行仍能看到完整原文。
