## 2. 缺口：要成为"完整可用"还差什么

### 2.0 已经补上的一个小口子：数据新鲜度官

**为什么先做它**：实测发现本仓库快照停在 **09-19 07:16 UTC**，而墙钟是 **09-20 16:08**
—— **滞后 33 小时**，而页面上只有一行小字写着快照时刻，**没有任何地方说"它有多旧"**。

它的关键设计是**区分两种"旧"**（否则这个提示会恒红，等于没有信号）：

| 模式 | 判据 | 处置 |
|---|---|---|
| `declared_offline` | `basis=asof`（读冻结快照） | 如实标注，**不报警** —— 旧是声明过的模式，且结论因此可复跑 |
| `stale` | `basis=wallclock`（实时）但输入落后 > `DATA_FRESH_MIN=30` 分钟 | **报警** —— 实时模式下输入停了最危险："行情停滞""报价冻结"这些**按龄判据**会全部失真，而结论看起来很正常 |

实测（真实数据，不是合成）：`asof -> declared_offline`；`wallclock -> stale`
（最旧的是「情绪/资金费」，`sentiment-2026-09-18.csv`，滞后 2867 分钟）。
—— 顺带查出一个此前没人注意到的事实：**情绪数据比其余源又早了一整天**。

页面：顶栏一行 + **只在危险时**弹横幅（离线模式用安静样式）。
`/api/health` 与 `/api/decision` 都带 `freshness`。

### 2.1 缺口清单

| # | 角色 | 为什么必须有 | 需要什么输入 | 现在能不能做 |
|---|---|---|---|---|
| **P0-1** | **采集官** | 🔴 **本仓库自己不采集**。`recover_sampling.py` 只做诊断；`data/spread/*.csv` 是冻结快照；真正的采样器在**项目一**（`tools/check_samplers.py`、`scripts/sampler_supervisor.ps1` 都在那边）。实测：项目一的采样器**正在写**（文件时间 00:08），而本仓库快照停在 09-19 | Bitget **公开行情**（无需账号）+ 本机代理 `127.0.0.1:7890`（实测走代理 3/3 通，直连被 ISP 掐断） | ✅ **能**，且不需要任何账号 |

| **P1-5** | **日报官** | 每日汇总：决策数、被否原因分布、告警、采集健康。真实运维需要一个"今天发生了什么"的入口 | 本地日志（`data/run/record.jsonl`、`data/reports/*`） | ✅ 能 |
| P2-6 | 多账户与限额 | 多交易所/多账户时的敞口合并与限额 | 各所只读 key | ⏳ 等 P0-2 落地后 |

## 3. 交易所接入（Bitget）：接口与红线

### 3.1 只读是**权限层面**的，不是"我们保证不写"

- 在 Bitget 创建 API key 时**只勾「读取」**，**不要**勾交易、提币、划转。
- 建议**同时**开 IP 白名单（只允许本机出口 IP）。
- 代码侧再加一层：接入层只实现**查询类**端点，**不实现**任何下单端点（沿用 §0 的核验方式）。

### 3.2 签名（Bitget v2）

```
ACCESS-SIGN = base64(HMAC-SHA256(secret, timestamp + method + requestPath + body))
```

只读查询的 `body` 为空串；`timestamp` 是毫秒。**这条要实现成纯函数并单测** ——
签名错了会表现为"403 权限不足"，很容易被误判成"key 权限没开"。

### 3.3 降级（比功能更重要）

| 情况 | 必须的行为 |
|---|---|
| 没配 key | 明确标注「**未接账户**」，继续用文件式持仓单；**不假装有仓位** |
| key 无效 / 权限不足 | 明确报错并**指到具体端点和返回码**；不静默回退成"空仓位"（空仓位 = 看起来像"没有风险"） |
| 网络/代理不通 | 同上；带重试与超时，且**记录失败次数**（这本身是采集健康的证据） |

> ⚠️ "空仓位"和"读不到仓位"**必须是两种不同的显示**。这是本项目一贯的规矩：
> **没有数据 ≠ 没有风险**。

## 4. 数据采集：三条路，推荐 B

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A** 现状 | 项目一采样 → `tools/export_p2_snapshot.py` 导出到本仓库 | 已经能用；两仓库职责清晰 | 本仓库**不能独立持续采集**；加标的要动项目一（见 `docs/50`） |
| **B** ⭐ 推荐 | 本仓库**自带采集器**（Bitget 公开 REST/WS，无需账号） | 本项目**独立**、格式与现有快照一致、`docs/50` 的"加标的"不再依赖项目一 | 要处理断线重连、代理、去重；约 1 个新工具 + 自检 |
| C | 直接对接交易所 WebSocket | 最实时 | 复杂度最高；且本项目的判据都是**分钟级**的，WS 的毫秒优势用不上 |

**推荐 B 的理由**：本项目的判据（点差、深度、成交笔数）都是分钟级采样，
**公开 REST 足够**；而"能不能自己拿到数据"决定了它是不是一个**能独立运行的系统**。

### 4.1 一个必须写清的时间事实

```
现在（写本文时）  : 2026-09-20 16:1x UTC = 09-21 00:1x 北京
in_house 路由窗口 : 09-19 08:00 北京 开 → **09-21 08:00 北京 关**（约 8 小时后）
```

`recover_sampling.py` 的原文：「窗口内的盘口**不可回补**」。
好消息：**项目一的采样器正在持续写**（本轮实测文件时间是 00:08），所以窗口内的数据
**正在被捕获**，不存在"8 小时内必须做什么"的紧急情况。
要做的是**把新鲜数据搬进来**（方案 A 的导出，或方案 B 的自采）。

⚠️ 但**不要**在提交前随手重导快照：本仓库的 `data/` 是**已验证的证据基座**
（26 项冻结哈希、`--verify` 逐字节通过，材料里引用的每个数字都点回它）。
换快照 = 换证据基座，所有实测数字都要重测。**这是一次单独的、要留出时间的动作。**

## 5. 落地顺序与验收标准

| 顺序 | 做什么 | 验收（**能失败**的那种） |
|---|---|---|
| 1 | **采集官**（方案 B） | 跑 5 分钟，`data/spread/*` 出现新行；`data_freshness(basis=wallclock)` 从 `stale` 变 `ok` |
| 2 | **仓位官**（只读，含降级） | 配 key 后页面出现真实持仓；**拔掉 key** 后页面明确写「未接账户」，**而不是显示 0 仓位** |
| 3 | **对账官** | 给出逐笔「建议价 vs 成交价」差；没有成交时明确说"没有可对账的成交" |
| 4 | **复核/离场官** | 每条触发条件都能被一个具体观测**证伪**；且**不输出任何价位** |
| 5 | **日报官** | 一条命令给出当日：决策数 / 被否原因分布 / 告警 / 采集健康 |

## 6. 需要你提供什么

1. **Bitget 只读 API**：key / secret / passphrase，权限**只勾读取**（建议同时开 IP 白名单）。
2. 是否允许把交易所返回的持仓快照**落盘**（默认只落脱敏后的字段：symbol / size / 均价；
   不落账号、不落 key 指纹以外的凭据）。
3. 交易标的范围（现在快照是 10 个：NVDA/TSLA/AAPL/META/GOOGL/SPY/QQQ/SOXL/HOOD/MRVL）。
4. 用哪条采集路线（推荐 B，自带采集器）。
