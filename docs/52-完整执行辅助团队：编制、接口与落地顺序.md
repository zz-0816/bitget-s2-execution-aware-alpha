## 2. 缺口：要成为"完整可用"还差什么

### 2.0 已经补上的一个小口子：数据新鲜度官

**为什么先做它**：实测发现本仓库快照停在 **09-19 07:16 UTC**，而墙钟是 **09-20 16:08**
—— **滞后 33 小时**，而页面上只有一行小字写着快照时刻，**没有任何地方说"它有多旧"**。

它的关键设计是**区分两种"旧"**（否则这个提示会恒红，等于没有信号）：

| 模式 | 判据 | 处置 |
|---|---|---|
| `declared_offline` | `basis=asof`（读冻结快照） | 如实标注，**不报警** —— 旧是声明过的模式，且结论因此可复跑 |
| `stale` | `basis=wallclock`（实时）但输入落后 > `DATA_FRESH_MIN=30` 分钟 | **报警** —— 实时模式下输入停了最危险："行情停滞""报价冻结"这些**按龄判据**会全部失真，而结论看起来很正常 |

实测（真实数据，不是合成）：`asof -> declared_offline`；`wallclock -> stale`
（最旧的是「情绪/资金费」，`sentiment-2026-09-18.csv`，滞后 2867 分钟）。
—— 顺带查出一个此前没人注意到的事实：**情绪数据比其余源又早了一整天**。

页面：顶栏一行 + **只在危险时**弹横幅（离线模式用安静样式）。
`/api/health` 与 `/api/decision` 都带 `freshness`。

## 3. 交易所接入（Bitget）：接口与红线

> ⚠️ **本节描述的是「备选路线」（自建 API Key）**。2026-09-21 定案：**主路线走 Agentic 账户
> OAuth**（§8），那条路线**不需要你提供 key**、也不需要自建签名。
> 本节保留的理由：备选路线是**唯一可以实现"自动轮询"**的一条，
> 而 Agentic 路线是**手动触发**的 —— 取数已实现（`python tools/account_read.py --read`），
> 但仍要有人敲那一条命令（见 §8.3）。
> 若将来要求账户数据自动刷新，再回到本节。

### 3.1 只读是**权限层面**的，不是"我们保证不写"

- 在 Bitget 创建 API key 时**只勾「读取」**，**不要**勾交易、提币、划转。
- 建议**同时**开 IP 白名单（只允许本机出口 IP）。
- 代码侧再加一层：接入层只实现**查询类**端点，**不实现**任何下单端点（沿用 §0 的核验方式）。

### 3.2 签名（Bitget v2）

```
ACCESS-SIGN = base64(HMAC-SHA256(secret, timestamp + method + requestPath + body))
```

只读查询的 `body` 为空串；`timestamp` 是毫秒。**这条要实现成纯函数并单测** ——
签名错了会表现为"403 权限不足"，很容易被误判成"key 权限没开"。

### 3.3 降级（比功能更重要）

| 情况 | 必须的行为 |
|---|---|
| 没配 key | 明确标注「**未接账户**」，继续用文件式持仓单；**不假装有仓位** |
| key 无效 / 权限不足 | 明确报错并**指到具体端点和返回码**；不静默回退成"空仓位"（空仓位 = 看起来像"没有风险"） |
| 网络/代理不通 | 同上；带重试与超时，且**记录失败次数**（这本身是采集健康的证据） |

> ⚠️ "空仓位"和"读不到仓位"**必须是两种不同的显示**。这是本项目一贯的规矩：
> **没有数据 ≠ 没有风险**。

## 4. 数据采集：三条路，推荐 B

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A** 现状 | 项目一采样 → `tools/export_p2_snapshot.py` 导出到本仓库 | 已经能用；两仓库职责清晰 | 本仓库**不能独立持续采集**；加标的要动项目一（见 `docs/50`） |
| **B** ⭐ 推荐 | 本仓库**自带采集器**（Bitget 公开 REST/WS，无需账号） | 本项目**独立**、格式与现有快照一致、`docs/50` 的"加标的"不再依赖项目一 | 要处理断线重连、代理、去重；约 1 个新工具 + 自检 |
| C | 直接对接交易所 WebSocket | 最实时 | 复杂度最高；且本项目的判据都是**分钟级**的，WS 的毫秒优势用不上 |

**推荐 B 的理由**：本项目的判据（点差、深度、成交笔数）都是分钟级采样，
**公开 REST 足够**；而"能不能自己拿到数据"决定了它是不是一个**能独立运行的系统**。

## 8. 路线定案（2026-09-21）：主 Agentic，API Key 作备选

用户 2026-09-21：「**都做，其中主要走 agentic 路线**」。据此定案：

| | 🟢 **主路线：Agentic 账户（OAuth）** | 🟡 备选：自建只读 API Key |
|---|---|---|
| 授权方式 | OAuth（`authorize_start` → 浏览器 → App 设备验证） | 官网手工建 key，自己签名 |
| 凭证 | MCP 回调**自动落盘**，用户不接触 | 用户手工粘贴进 `.env` |
| 隔离 | **独立资金域**，Agent 只能碰转进去的额度 | 共享主账户余额 |
| 提币 | **不能**（官方 FAQ 明确） | 取决于勾了什么权限 |
| 撤销 | 官网删该账户的 API Key（**不会自动平仓/撤单**） | 删 key |
| 泄露面 | 小（无长期 key 落在聊天/文档里） | **大** —— 项目一 `docs/54` §6.2 自认"最现实的一条" |
| 自动化程度 | 取数**已实现**，但仍是**手动触发**（一条命令；不做自动轮询） | 可实现自动轮询 |

**为什么主 Agentic**：① 它的三个性质（资金隔离、不可提币、OAuth 不落 key）
正好对上本项目"**只辅助、不自动下单**"的定位 —— 权限边界由交易所这一侧兜住，
而不是靠"我们保证不调用"；② 不用把长期密钥交到任何对话/文档里。

**代价（如实说）**：Agentic 路线下，账户数据**不是自动刷新的** ——
每次要新数据，得手工敲一条取数命令（`tools/account_read.py --read`）再 `--ingest`。
这对"演示 + 人工复核"够用；如果将来要求"打开页面就是最新持仓"，那要回到备选路线（§3）。

| 项 | 实测值 | 含义 |
|---|---|---|
| 授权 | `authorized: true`（apiKey 由服务端掩码成 `bg_ff…7fe4`） | OAuth 生效 |

| 永续费率 | maker 0.0002 / taker 0.0006 = **2 / 6 bp** | 与 `project2/execution_cost.py` 的 `FEE_PERP_MAKER/TAKER` **逐项一致** |
| 现货 rToken 费率 | 0.0005 / 0.0005 = **5 / 5 bp**（`RHOODUSDT`）| 与 `FEE_SPOT` 一致 |

> 为什么这条重要：`EDGE_THRESHOLD_BP = 11.34` 的推导前提就是
> 「往返手续费 13.70 bp = 2×(现货 5.0 + 永续 maker 2.0)」。**费率一旦漂，门槛就得重算** ——
> 所以 `--preflight` 把这五个数与 `execution_cost.py` 逐项对照，漂了就报警并点明这一点。

两个**此前不知道**的事实（都会影响结论，已写进工具注释与自检）：

1. **费率是逐 symbol 的** —— 同为 SPOT，`BTCUSDT` 是 **10 bp**、`RHOODUSDT` 是 **5 bp**。
   所以前置检查必须按**自己的标的**查；拿 BTC 的费率当代表就是错的。
2. **`category=SPOT` 的 positions 段不被支持**（返回 `HTTP 400 / Parameter SPOT does not exist`）
   —— 现货持仓不在这里。工具**如实报出**，而不是把它当成"空仓"。

⚠️ **仍未校准的一处**，如实标出来：**非空持仓的字段名**。当前账户为空，拿不到真实非空返回，
所以 `--preflight` 遇到非空持仓时**原样贴出**并明确警告「未校准、请人工核对」，
不按猜出来的字段名硬解读。
