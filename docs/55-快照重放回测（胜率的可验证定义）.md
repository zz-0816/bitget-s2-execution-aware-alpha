## 0. 一句话结论

**在冻结快照的 15.3 小时窗口里，系统自己的门槛（11.34 bp）对"双腿做市"信号有
真实且可复算的甄别力**：过门槛的信号在所内撮合窗口（in_house）按 maker 口径
**胜率 84.6%~100%、均值 +12.3~+16.2 bp、最差单笔仅 −5.7 bp**；
而不过滤的基线胜率只有 9.8%~13.3%（均值 −14~−16 bp）。
**吃单路线 0% 胜率**（同信号下均值 −43~−48 bp）—— 用数据复现了 docs/14
"从吃单套利正名为做市型价差捕获"的路线判断。
**但样本只有 30 笔信号（集中在 1 个标的）、且 maker 口径是乐观上界** ——
这些数字证明的是"门槛与成本模型的方向是对的"，**不是**"实盘能赚钱"（§5）。

## 1. 为什么不是传统回测（这部分是结论，不是免责声明）

| 传统回测需要什么 | 本项目有什么 | 后果 |
|---|---|---|
| 完整历史行情（数年） | **轮级盘口只有一天**（2026-09-19，60s 一轮，15.3h，10 标的×双腿） | 样本窗口小，只能证方向，不能证长期 |
| 挂单成交记录（含队列位置） | **没有队列数据**；本项目也从未建队列位置模型（docs/40 已列为局限） | maker 成交率**不可测** → maker 口径只能是"假设成交在自己报价上"的乐观上界 |
| 历史事件流（重放 LLM 判定） | 事件是当时的信息，事后重放 = 编造 | 信号规则**只用确定性成本层**（门槛+费率+盘口），LLM 不参与 |
| 逐笔资金费结算 | 快照无此记录 | 资金费**声明排除**（H ≤ 60min 影响量级小，但方向未知） |

> README §7 的"材料里不要写的三条"之一就是 *"用周末样本跑了 60 天回测"*。
> 本文档与那条红线一致：**所有数字都标明窗口、口径与假设，一个都不外推。**

## 2. 重放规则（确定性，任何人可复跑）

```
数据   data/spread/2026-*.csv（轮级盘口，冻结快照，只读）
对齐   每 base 把 perp 轮按 ts_ms 就近对齐到 spot 轮（容差 ±15s）
信号   edge = 2×(half_s + half_p) − 往返手续费 ≥ EDGE_THRESHOLD_BP (11.34)
       half_* = 快照真实盘口的 spread_bp / 2
       费率从 project2/execution_cost.py 读；门槛从 project2/agent_team.py 读
       路由从 common/market_calendar.route_of() 判（快照窗口横跨两种计费制度）
       ⚠️ 公式里的"逆向选择 f"不单独减 —— 重放的实际结果里已隐含它
出场   t+H（H ∈ 15/30/60 分钟），按出场轮真实中间价估值；无法出场单独计数
不重叠 每 base 触发后 H 分钟内不再触发（60s 节奏下相邻轮高度自相关）
基线   全体对齐轮不过滤直接进场（同样的不重叠规则）
```

**两条口径并列报告**（不给挑有利口径的机会）：

| 口径 | 进出假设 | 手续费 | 含义 |
|---|---|---|---|
| **taker 保守下界** | 进出都按对手价（付两腿半幅点差） | 2×(5+6) = **22 bp** | 现实下界：如果只能吃单，这套系统值不值 |
| **maker 乐观上界** | 进出都按自己报价成交（赚两腿半幅点差） | in_house 2×(5+2)=**14 bp**；stockroute 按Taker | 乐观上界：假设挂单都在自己报价上成交 |

价格腿：对冲持仓的已实现盈亏 = ((S_H−S_t) − (P_H−P_t)) / S_t × 1e4 bp。
两腿对冲后剩下的就是 **rToken↔永续的基差漂移** —— 这是策略真实承担的风险，快照如实给出。

## 4. "胜率"的精确定义（避免歧义）

**胜率 = 在满足门槛信号、且窗口内存在出场轮的那些交易里，
按该口径计算的净盈亏（含手续费、含进出半幅点差处理）大于 0 的占比。**

- 每一笔都可复核：`data/backtest/replay_signals.csv` 逐行给出
  `ts_utc / base / route / edge / 两腿半幅点差 / 两口径盈亏`。
- 无法出场（信号在窗口末尾）的信号**不计入胜率**，单独报告（本次为 0 笔）。
- 样本极小（6~15 笔/格）→ 胜率的 95% 置信区间宽达 ±20~30 pp，
  **这些胜率只能当方向性证据，不能当统计结论**。

## 5. 这份证据支持什么、不支持什么

**支持（方向性）**：

1. **门槛有真实甄别力**：过门槛信号 vs 不过滤基线，胜率差 +53~+64 pp、均值差
   +12~+21 bp —— 这是对"系统的核心判据（11.34 bp）是否有效"的直接检验。
2. **吃单路线被数据判死**：同信号下 taker 胜率 0%、均值 −43~−48 bp，
   复现了 docs/14 的路线判断（22 bp 往返费 + 点差吃穿）。
3. **stockroute 的宽点差是陷阱**：stockroute 里过门槛的"信号"均值 −38~−48 bp ——
   因为挂单按 Taker 计费、且极宽点差意味着流动性极差。这**用数据复现了**
   DATA_DICT §1 "stockroute 下 maker 无意义" 的口径（费率规则来自官方公告，
   这里的贡献是展示了**违反它会亏多少**）。
4. **in_house + maker 是唯一成立的组合**：84.6%~100% 胜率、最差单笔 −5.7 bp。

**不支持（明确不外推）**：

1. **不证明实盘能赚钱**：maker 口径假设成交发生在自己报价上（无队列成本）；
   实测联合分布 P(两腿成交)=0.70%、P(单腿)=24.9% —— 现实可实现性要按它折算，
   且现货腿自 09-14 起零成交（docs/29）。
2. **不证明长期有效**：窗口只有一天、且集中在 1 个标的（HOOD，占 27/30 笔信号；
   其余 3 笔来自 MRVL）。
3. **不包含 agent 链**：LLM 事件判定、辩论、风控官无法历史重放 ——
   本回测验证的是**定量成本层**（门槛+费率+盘口），那也是数字唯一可靠的部分。
4. **不含资金费**：H ≤ 60min 影响量级小，但方向未知，声明排除。

## 6. 与既有证据的关系（三块证据互相咬合，没有一块单打独斗）

| 证据 | 回答的问题 | 出处 |
|---|---|---|
| 摩擦预算 `friction_budget.csv` | 一笔单的成本结构（点差/费/冲击/逆向选择） | docs/14 |
| 实测联合成交分布 `joint_fill_*.csv` | 挂单**能不能成交**（P 两腿/单腿） | docs/29、docs/14 §5 |
| **快照重放（本文档）** | 过了门槛的信号，**事后真的收敛吗**（胜率/均值/尾差） | `data/backtest/` |

三块分别覆盖"成本结构 / 成交概率 / 信号质量"，合起来才是"可行性"的完整回答 ——
而它们都建立在同一份冻结快照上，全部可复跑。
