## 0. 一句话结论

**在快照 4.5 天窗口里，系统自己的门槛（11.34 bp）对"双腿做市"信号有真实且可复算的
甄别力**：过门槛的信号在**所内撮合窗口（in_house）**按 maker 口径
**胜率 84.9%~92.0%、均值 +16.2~+18.2 bp**（33~112 笔/格），
而不过滤的基线胜率只有 **8.3%~10.7%**（均值 −19~−20 bp）——
**门槛增量 +41~+61 个百分点**。同信号下 **taker 胜率 0%**（均值 −49~−53 bp），
用数据复现了 docs/14「从吃单套利正名为做市型价差捕获」的路线判断。
**但**：样本仍只覆盖 3 个有信号的交易日、4 个标的；maker 口径是**乐观上界**
（无队列位置模型）——所以它证明的是"门槛与成本模型的方向对"，**不是**"实盘能赚钱"（§5）。

## 1. 为什么不是传统回测（这部分是结论，不是免责声明）

| 传统回测需要什么 | 本项目有什么 | 后果 |
|---|---|---|
| 完整历史行情（数年） | 轮级盘口 **4.5 天**（2026-09-19~09-23，60s 一轮，10 标的×双腿） | 只能证方向与稳定性，不能证长期 |
| 挂单成交记录（含队列位置） | **没有队列数据**；本项目也从未建队列位置模型（docs/40 已列为局限） | maker 成交率**不可测** → maker 口径只能是"假设成交在自己报价上"的乐观上界 |
| 历史事件流（重放 LLM 判定） | 事件是当时的信息，事后重放 = 编造 | 信号规则**只用确定性成本层**（门槛+费率+盘口），LLM 不参与 |
| 逐笔资金费结算 | 无此记录 | 资金费**声明排除**（H ≤ 60min 影响量级小，但方向未知） |

> README §7 的"材料里不要写的三条"之一就是 *"用周末样本跑了 60 天回测"*。
> 本文档与那条红线一致：**所有数字都标明窗口、口径与假设，一个都不外推。**

## 2. 重放规则（确定性，任何人可复跑）

```
数据   data/spread/2026-*.csv（轮级盘口，冻结快照，只读）
       当前窗口 = 2026-09-19 / 09-20 / 09-21 / 09-22（09-23 为进行中的部分日）
对齐   每 base 把 perp 轮按 ts_ms 就近对齐到 spot 轮（容差 ±15s）
信号   edge = 2×(half_s + half_p) − 往返手续费 ≥ EDGE_THRESHOLD_BP (11.34)
       half_* = 快照真实盘口的 spread_bp / 2
       费率从 project2/execution_cost.py 读；门槛从 project2/agent_team.py 读
       路由从 common/market_calendar.route_of() 判（窗口横跨两种计费制度）
       ⚠️ 公式里的"逆向选择 f"不单独减 —— 重放的实际结果里已隐含它
出场   t+H（H ∈ 15/30/60 分钟），按出场轮真实中间价估值；无法出场单独计数
不重叠 每 base 触发后 H 分钟内不再触发（60s 节奏下相邻轮高度自相关）
基线   全体对齐轮不过滤直接进场（同样的不重叠规则）
```

**两条口径并列报告**（不给挑有利口径的机会）：

| 口径 | 进出假设 | 手续费 | 含义 |
|---|---|---|---|
| **taker 保守下界** | 进出都按对手价（付两腿半幅点差） | 2×(5+6) = **22 bp** | 现实下界：如果只能吃单，这套系统值不值 |
| **maker 乐观上界** | 进出都按自己报价成交（赚两腿半幅点差） | in_house 2×(5+2)=**14 bp**；stockroute 按 Taker | 乐观上界：假设挂单都在自己报价上成交 |

价格腿：对冲持仓的已实现盈亏 = ((S_H−S_t) − (P_H−P_t)) / S_t × 1e4 bp。
两腿对冲后剩下的就是 **rToken↔永续的基差漂移** —— 这是策略真实承担的风险，快照如实给出。

## 4. "胜率"的精确定义（避免歧义）

**胜率 = 在满足门槛信号、且窗口内存在出场轮的那些交易里，
按该口径计算的净盈亏（含手续费、含进出半幅点差处理）大于 0 的占比。**

- 每一笔都可复核：`data/backtest/replay_signals.csv` 逐行给出
  `file / base / ts_utc / route / edge / 两腿半幅点差 / 两口径盈亏`（292 行）。
- 无法出场（信号在窗口末尾）的信号**不计入胜率**，单独报告。
- 样本 33~112 笔/格 → 胜率的 95% 置信区间约 ±6~16 pp，
  **比 v1 窄得多，但仍只能当方向性证据、不能当收益承诺**。

## 5. 这份证据支持什么、不支持什么

**支持（方向性，且跨日稳定）**：

1. **门槛有真实甄别力**：过门槛信号 vs 不过滤基线，胜率差 +41~+61 pp、
   均值差 +9~+20 bp —— 直接检验了"11.34 bp 门槛是否有效"。
2. **吃单路线被数据判死**：同信号下 taker 胜率 0%、均值 −49~−53 bp。
3. **stockroute 的宽点差是陷阱**：37/27/21 笔"信号"均值 −52~−54 bp ——
   宽点差意味着流动性极差且挂单按 Taker 计费，复现了 DATA_DICT §1 的口径。
4. **in_house + maker 是唯一成立的组合**：胜率 84.9%~92.0%、均值 +16~+18 bp。

**不支持（明确不外推）**：

1. **不证明实盘能赚钱**：maker 口径假设成交发生在自己报价上（无队列成本）；
   实测联合分布 P(两腿)=0.70%、P(单腿)=24.9% —— 现实可实现性要按它折算。
2. **不证明长期有效**：4.5 天窗口、3 个有信号的交易日、4 个标的（均来自周末
   所内撮合窗口的样本形态）。
3. **不包含 agent 链**：LLM 事件判定、辩论、风控官无法历史重放 ——
   本回测验证的是**定量成本层**（门槛+费率+盘口）。
4. **不含资金费**：H ≤ 60min 影响量级小，但方向未知，声明排除。

## 7. 补数据时的两条发现（其中一条是**我自己的过度推断被数据打脸**）

补入项目一 09-20~09-23 样本时，先把"现货腿成交"这件事查了一遍。两条结论：

### 7.1 `docs/29` 的"零成交"结论**是对的**（别改）

原始数据逐笔核对：`trades-2026-09-14.csv` 里那 3445 笔现货成交，时间戳全部落在
**09-13T16:00–22:59Z**（北京 09-14 凌晨、美股周五盘中）—— 也就是
**09-14T00:00Z 零成交开始之前**。与 `docs/29` 的
"零成交 09-14 00:00Z → 09-19 06:46Z，之后恢复"逐字吻合。

> ⚠️ **我曾据"项目一原始文件有 3445 笔、旧快照 0 笔"推断 docs/29 是快照截断造成的
> 假结论 —— 这个推断是错的。** 旧快照的 09-14 文件（尾部 8 万行 = 09-14T14:14→15:59Z）
> 确实落在零成交期里，所以它有 0 笔现货是**正确**的，不是伪影。
> 教训：**"两个数据源数字不一致"不等于"其中一个错了"** —— 先对齐时间窗，再下结论。

### 7.2 真正的新发现：**09-22 又出现整天零成交**（旧快照看不到）

| 日期 | 现货成交 | 说明 |
|---|---|---|
| 09-14 | 3445（全部在 09-13T16:00–22:59Z） | 零成交于 09-14T00:00Z 开始 |
| 09-15 ~ 09-18 | 0 | 与 docs/29 一致 |
| 09-19 | 1527 | 06:46Z 后**恢复** |
| 09-20 | 4206 | 正常 |
| 09-21 | 2946 | 正常 |
| **09-22** | **0**（同期永续 509,515 笔） | 🔴 **第二次整天零成交** |
| 09-23 | 0（当日进行中） | — |

这条是**旧快照无法发现的**（它停在 09-19）。它直接解释了两件事：
① 页面上"全站不参与"里的 `agent:stale_quotes` / `quote_frozen` 是**真判据在起作用**
（现货腿最后成交在 09-21T22:59Z，对 09-22T15:59Z 的基准已过 17 小时 > 30 分钟阈值）；
② **现货挂单路径此刻确实不可执行**，而不是系统算错了。

### 7.3 顺带修掉的截断缺陷（这条是真的）

旧规则"trades 只留尾部 8 万行"会**丢掉当日后半段的现货行**（09-19：原始 1527 → 快照 611，
少了 916 笔）。虽未造成 7.2 那种错误结论，但会让"最后一笔现货成交距今"**偏早**，
直接影响 `stale_quotes` 的年龄计算。

**现行规则（已写进 `tools/snapshot_manifest.py` 的 `TRADES_NOTE`）：
现货行一条都不许丢，永续行可截尾。**

> 教训：**截断规则要按"数据的稀缺性"设计，而不是按"文件大小"**。
> 用同一个"尾部 N 行"去截两个成交量差 100 倍的市场，等于系统性删掉稀的那一侧 ——
> 而稀的那一侧恰恰是停牌/成交率判据所依赖的。
